# 0.6.1 档案补全、分类与清理

日期：2026-09-25。修改前的本卡 Git 基线为 `028bbb4a`（0.6.0）。本轮只处理用户截图中的三项问题，未接入新玩法；光栅卡实验、镜待流年和系统流不参与构建或提交。

## 原因与修改

1. **正文引用成功输出，但档案未落库。** 原修复组件只在 `_待修复` 非空时显示，无法发现成功批次中的遗漏。已用 `<EmbersCard type="note" id="harbor_mirror"/>`、正常存档和空 `_待修复` 重现。0.6.0打包界面的浏览器用例也确认找不到补全入口。
   - 状态栏检测本楼正文中的缺失人物/见闻引用，展示“前往补全档案”。
   - 在“行动”逐项选择、补充依据、生成候选，核对后保存；候选可以是新记录，也可以关联已有记录ID。
   - 知情范围之外的既有见闻、手动移除的资料不作为新建缺口。已失败的结算批次仍走原来的局部修复。
   - 补全只处理选中的档案，不再次运行本轮时间与数值动作；能力、物品等数值问题仍通过原结算修复和补记处理。

2. **人物/生物混放，以及动作被登记成生物。** 原人物页同时筛选了两类实体；旧 `encounter` 操作还会将传入名称直接套成60/18/10等数值模板，类别固定为生物。离线重现得到与截图相同的“催收壮汉的袭击”。
   - 人物与生物有独立页签，人物档案与数值实体按稳定ID合并展示。
   - 新回复统一通过 `register` 登记实际个体，`strike` 表达攻击，`exposure` 表达环境作用。旧 `encounter` 保留读档执行兼容，从默认模型契约与新回复规则中退出。
   - 旧错档可在详情中“编辑实体分类”，核对名称、分类及人物档案关联；程序不靠名称猜测其身份。

3. **缺少手动清理。** 人物、实体、见闻详情可移除；“整理”集中支持人物、实体、见闻、能力、物品、事项的查询、确认移除和恢复。
   - 移除采用可恢复的档案标记，退出状态栏列表和后续变量投影；人物/实体的关联档案、见闻和关系一并退出收录。
   - 数值账本、历史正文及能力实际效果保留；这不是销毁物品、解除能力或改写既有剧情。聊天世界书中的独立设定不在此处删除。
   - “已移除”列出直接移除的来源，恢复该来源后，关联资料恢复；分别移除的子记录仍保持各自选择。

## 数据与维护入口

- `src/card-recovery.ts`：缺失检测、单条补全提示词、候选校验、已有ID关联。
- `src/archive-tools.ts`：人物/生物分组、移除影响范围与整理列表。
- `src/local-archive.ts`：手动编辑按本楼原文回执记录在 `message.data.embers_local_archive`，由 MVU 事件入口在同楼重解析后恢复。变更限定于档案、引用、移除标记、实体名称和类别。
- `src/settlement.ts`：全部写入仍检查聊天、楼层、消息页和所见快照；互斥保存后回读。
- `_档案整理` 与 `_档案引用` 是脚本维护字段，旧档读取时自动补默认值。整理记录留在存档，不作为常驻提示词发送。
- `界面/状态栏/MissingArchives.vue`、`ArchiveRemove.vue`、`ArchiveManager.vue`：补全、移除确认、恢复。
- `src/prompt-view.ts` 会直接序列化进 EJS；内部筛选保持自包含，不能只添加外部函数导入。

## 世界书文字衔接

本轮修改只对齐程序契约：正文格式明确记录ID和对象ID的区别、新卡片引用与同轮落档；人物档案说明持续角色与临时背景人物的建档时机；首次/日常更新规则补充引用与记录对应；行动规则统一实际个体登记。未新增针对截图对象的专用规则。

后续文字协作沿用《世界书写作规范.md》。人物、生物是对象分类，攻击是动作；档案、数值实体与正文引用应共享可追踪的身份。世界书侧继续完善一般规律，不为每次模型遗漏追加具体例子和禁令。

## 验收与测试入口

- 137项自动测试、TypeScript与Lint；包含真实MVU脚本事件入口的离线回放，以及EJS合并/重复编译。
- 四组浏览器模拟套件：旧封面、正文小卡、工坊、进化与变量修复回归；新补全生成失败/取消/预览/确认、过期快照/切换聊天拒写、人物生物分栏、分类修订、移除与恢复；覆盖1000/390/320宽度，并检查正文卡片随档案更新而就地显示。
- PNG打包核验包含世界书清单、负载与原头像图像块。日志位于 `tests/logs/`，截图位于 `build/verification/0.6.1/`。
- 浏览器与MVU回放使用模拟酒馆接口，没有调用用户真实模型，也没有修改真实聊天。模型是否稳定按新规则落档仍需用户实际游玩验证。

卡包：`release/0.6.1/余烬之后-0.6.1.png`。请由用户导入或更新本卡并使用新版本脚本、世界书、正则和界面；旧楼层已经嵌入的旧版界面不会因源码升级自动更换。建议保留原聊天副本后测试。

测试重点：正文缺失见闻时出现“前往补全档案”；生成后先核对候选再保存；普通生物在“生物”页；不需要的路人可移除并在“整理→已移除”恢复。
