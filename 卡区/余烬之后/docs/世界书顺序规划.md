## 插入顺序的真实含义

先比较插入位置、深度与角色，再在同位置比较顺序数字。不能认为 D0 的 7100 与角色定义前的 1100 处于同一个全局排序队列。

getwi 读取关闭条目后，文本出现在调用它的 EJS 控制器处。源条目的 16000 不会把它移动到控制器之后的另一个位置；开局内容实际继承 3400。一个控制器读取多个条目时，按 print 的执行顺序输出。源条目保持关闭，避免重复注入。

传承控制器在实际获得起源涅槃时读取种核、死亡复苏和伴生灵；人物与空间按当前地点及相关名称调用。开局控制器只在存在 first-return 且首次资料未完成时读取初次归泊，持有越界时读取该能力的独立资料。

未来增加开局：新增自己的初始化逻辑、稳定开局识别及关闭资料条目，在开局控制器加入条件。通用品阶、日常规则和角色档案不写入该开局的既定事故、奖励与首次关系。若开局数量继续增长，将路由声明抽为数据表，不堆叠全文条件。

## 验收

检查打包 JSON 中的 enabled、extensions.position/depth/role、insertion_order，以及绑定本版本世界书后的 EJS 实际输出。分别验证默认首次、首次完成、自定义未发生事故、无专属能力四种状态。排序测试只对同一插入位置的启用条目检查冲突。
