# 余烬之后

当前版本：0.4.1。虚海容纳多元位面，起源之母初微与终焉之母末墟维持生灭循环；默认主角由双母力量交融而生，自定义身世与机缘保持自由。

## 导入与游玩

导入 `release/0.4.1/余烬之后-0.4.1-dev.png` 及其内嵌世界书，启用本卡正则和酒馆助手脚本。卡名与主世界书均为“余烬之后 v0.4.1”。需要酒馆助手、提示词模板与MVU公共依赖。UI与用户原头像随包内嵌，头像原始字节和PNG图像块保留。

在独立封面选择默认或自定义角色、开局，预览开局要求后发送，由酒馆当前模型与预设生成第一幕。默认经历主世界车祸，在归泊庭首次重构，随后选择下一世界。封面的设定工坊可在开局前生成、编辑并导出人物与位面档案。

状态栏默认折叠。展开后为一个连续面板，分页包含概览、能力、行囊、见闻、归来、行动、变化。能力详情可把使用意图填入酒馆输入框，再补充目标和用法后发送；被动能力自动参与结算。行动页显示最近结果与可选提案，变化页比较楼层快照。

## 世界书组织

- `核心/`：多元位面总纲、故事基调。
- `系统/`：种核传承、起源涅槃、行动与结算。
- `角色/`：初微、末墟、艾斯特瑞亚。
- `空间/`：归泊庭。
- `位面/`：已有世界的详细资料与通行规则。
- `控制器/`：当前位面、传承人物与空间、首次/日常规则路由。
- `变量/`：初始化、当前变量视图、首次与日常更新规则、输出格式。

世界总纲与核心机制常驻；EJS仅读取当前位面详细资料。初微在相关剧情出现时加载，庭院在重构或相关剧情出现时加载。艾斯特瑞亚在种核苏醒后加载。条目文件、发布清单与EJS目标均独立于镜待流年。

未知世界通过旅行记录建立名称、简明背景、地点和时间倍率，保存在本局存档，EJS在抵达后读取；已有世界按名称归并到稳定ID，再次返回继续原有时钟。六个内置世界是资料样本，原创、同人和半位面均可在游玩中出现。

## 变量与结算

`_初始化完成`仅表示封面已经建立数值快照；`叙事.首次资料完成`决定首次/日常规则。首次全量填写现场、天气、关系、见闻、事件、摘要、时间和行动，最后标记完成。日常修改具体变化路径，同一事项沿用ID，合并重复内容、删除失效记录。

模型当轮可写`叙事`和`待审提案`。`叙事.本轮时间`记录已发生当地耗时；`叙事.本轮结算`按顺序记录已发生操作，脚本统一执行。可选行动放在待审提案，玩家确认后执行。相同快照与相同操作重解析保持同一结果，刷新不会推进时间。

MVU接收层保留原始时间与行动批次，本卡提交层使用严格schema整体校验；无效批次回到上一份有效状态，并将原因保存到`_更新错误`。状态栏与下一轮模型都能读取反馈，完成修正结算后清除。原失败输入保存在`_待修复`；行动页可校正生命或资源，填写依据并重试原更新，校正和重试采用同一事务。死亡自动进入庭院，达到重构完成时间后的revive才表示身体归来；同轮吸收与环境使用按exposure、channel顺序结算。

模型收到当前位面、在场实体、当前能力详情、简要索引、相关见闻、关系、事件与近期结果。能力详情至多20条、额外索引至多24条。按近期文字中的名称或ID检索，也能在界面选择重点能力或旧见闻取回。完整账本、未发现位面目录、旧开局大纲和归档不随每轮发送。常用见闻至多24项，较早记录归入本地旧页；当轮视图最多10项。关系最多8项、当地事件最多6项、最近结果最多4项。重要长期牵挂由记忆摘要保留。

初始生命100、能量50、攻击30、防御20、命中95%、闪避0%、暴击20%、暴伤1.5倍。默认开局已因卡车事故死亡，生命0、重构600秒，起源涅槃、终焉眷引与越界明确入册。自定义人设的原有能力仍作为背景资料，当前数值基线相同。

已接入：单目标攻防、命中/暴击/抗性、能量/冷却、环境暴露、新伤害机制登记、死亡适应、十分钟重构、复苏、被动转移与主动储能释放/环境应用、同位面移动和跨位面旅行。环境危害的强度与作用条件由模型依据正文给出，脚本负责扣血、适应上限、储能与一致性；开放文本的因果判断仍依赖模型。

复苏时世界继续、物品按绑定关系保留或掉落；新版死亡回到归泊庭完成重构，选择下一世界后启程；旧存档仍读取原有锚点。游戏时间取剧情刻度，位面时间＝本地基准秒＋经过起源秒×倍率。未知世界初到采用默认当地历与18:00基准；原有世界返回保持既有时钟。

尚未数值化的范围：多目标与持续状态、治疗、装备自动汇总、任意背景技能定标、物品与任务的通用增删结算。现有适应数值采用“对应机制转移与储能”统一模型；越界已具备独立的旅行、扣费与冷却规则；岁月免疫等特殊效果需后续实现。

## 身份与宏

酒馆仍按当前用户设定替换`{{user}}`。变量条目明确“本局 {{user}} 就是下列档案中的角色”，随后只提供本局档案的一份数据。自定义姓名、性别保存在本局；实体主键始终是player。独立的玩家称谓、控制权条目已移除，酒馆预设与用户设定管理保持原样。

## 构建与版本隔离

版本仅取自本目录package.json。卡名、主世界书名、EJS绑定、构建目录与包名统一派生，旧版产物保留。

```powershell
npm --prefix '卡区/余烬之后' run bump -- 0.4.2
npm --prefix '卡区/余烬之后' run pack
npm --prefix '卡区/余烬之后' run lint
npm --prefix '卡区/余烬之后' run preview
```

上面的0.4.2是下一次升版示例。本卡不调用根构建、根升版、其他卡同步或Git推送。世界书清单由tools/generate.cjs生成：核心背景在角色定义前；活动位面与行动说明在角色定义后；D0 system为当前变量100、规则200、正文格式250、输出格式300。

本地预览`http://127.0.0.1:8137/cover`展示封面，`/preview`为数值试演。完整回归见tools各测试；本轮审查与真实联调证据见`重构联调记录.md`。旧设计稿和0.1.1联调记录保留为历史。

## 0.2.0 游玩入口

- 默认开局：主世界车祸 → 归泊庭初次重构 → 选择下一世界。目的地可选预设，也可自由填写。
- 能力/行囊/见闻：点击标题，详情就在本条下方。能力显示品阶、等级、熟练度、转化量、储能、释放倍率；可填入行动或选择重点查阅。
- 行动：数值方案按当前状态确认执行，文字方案填回输入框商议；下面的补记与校正支持有依据的资源修正及失败更新重试。
- 进化：适应能力达到5/10/15级时，各可选择一次容纳、转化或释放，并提高品阶。
- 见闻：常用24条，旧页完整归档。搜索后可选入下一轮提示词。档案变长不等于每轮提示词线性变长；酒馆聊天历史仍由所用预设与上下文配置管理。
- 正文小卡：能力、物品、实体、见闻卡片读取同楼存档。未数值建模的人物/生物/物品可使用对应见闻卡呈现。D20探索检定补充原有攻防计算，本轮预先给出的骰列与脚本共用算法。

具体检查结果和已知范围见《0.2.0测试说明.md》。需要体验新版默认背景时新建聊天；用户负责导入和打开卡片。

## 0.3.0 游玩入口

- 行动页的「重新生成本轮变量」针对失败更新：可补充依据，调用当前酒馆模型，预览数值变化与完整补丁，校验通过后确认写回同楼正文中的更新块和变量；正文故事保留。停止、连接失败、切换聊天或消息页均不会自动提交候选。校正表单默认显示所选资源的当前值。
- 模型时间只填当地秒数，动作直接填数组。旧对象格式兼容；同楼同页文本回执避免重复结算。首次完整建档与日常增量仍分别调用。
- 「人物」页收录身份、性格、动机、说话方式、知识与关系经历，支持编辑及整理为世界书。资料保留在本局，每轮选取当前相关的最多6份。
- 「潮镜」页生成角色/位面，支持名称、风格、侧重、任意自定义设定和是否参考当前情境。预览可编辑全部JSON字段，保存到当前聊天绑定的世界书（未绑定时新建本局潮镜世界书）。只更新潮镜自己创建的对应条目，其他内容保留。条目默认关闭，注册到本局资料库后由EJS按当前位面、在场或近期名称调用。保存不会自动移动人物或开始剧情。
- 能力获得与进化、能力查阅、物品、人物、实体和见闻都有明确正文触发格式。能力获得卡默认展开，其他资料卡可折叠。位面与角色背景生成是叙事资料，战斗数值仍由已有操作定标。
- 新增「行动合理性」「世界与人物」「人物档案」「正文格式」独立世界书条目。
- 预览：`/cards`展示真实组件的能力获得卡、人物卡与潮镜示例；`/preview`展示完整状态栏。正式卡按钮使用酒馆当前模型，独立预览的生成按钮只载入示例。

测试与导入见《0.3.0测试说明.md》。此前导入的0.2.0仍包含旧脚本与规则，需要导入0.3.0后测试。

## 0.4.0 正文卡片与设定工坊

- `/cards` 是正文实景预览：传承印记、交锋、检定、死亡归泊、人物与物品、旅行与任务分别使用适合其内容的布局。卡片读取实际存档与结算；检定显示既有骰点，攻击可直接引用本轮操作序号。
- `/workshop` 是独立工坊预览。正式卡的封面和状态栏均可进入工坊，所有填写项可留空；展开后可选择常见属性，或逐项输入自定义设定。
- 人物生成涵盖身份、外貌、性格、经历、能力与局限、语言示例、关系、生活、随身物品与当前处境；位面生成涵盖概况、地理、历史、文明、力量、势力、独特现象、局势、探索地点与虚海联系。
- 草稿支持阅读、修改、复制和下载 Markdown，当前浏览器保留最近20份。游玩中的工坊还可保存到聊天世界书，由EJS按场景调用；开局前可先导出，交给作者完善后纳入正式世界书。
- 人物状态档案补充性别、年龄、种族、来源世界、能力与局限、背景经历、日常喜好。旧记录通过默认值兼容，每轮仍只发送相关人物摘要。

本地预览载入示例档案，正式卡调用当前酒馆模型。测试范围和体验步骤见《0.4.0测试说明.md》。

## 0.4.1 游玩反馈修复

- 档案尚未就绪时显示紧凑、可展开的“档案待同步”，技术详情收起；同楼变量补齐后自动替换为正式卡片。
- 失败变量以原失败输入为底稿，仅让AI修正报错路径。支持操作数组内单个字段；再次修复沿用候选，保留已修内容。界面先预览，确认后整体结算；楼层中可重解析的完整更新由程序重组。
- exposure的能力名称改为可选。已有机制沿用登记名，新机制缺省时使用“机制名称＋适应”；实际强度与作用条件仍校验。
- 工坊明确采用章节标题与纯文字字段。历史或新生成档案中的成对加粗标记在展示、导出、保存时统一整理。
- 正文格式明确分开通用规则和示例，死亡适应按实体ID与机制ID引用能力。

验证细节见《0.4.1测试说明.md》。
