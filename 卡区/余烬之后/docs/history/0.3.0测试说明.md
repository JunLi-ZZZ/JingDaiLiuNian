## 这轮建议体验

1. **失败变量重生**：失败楼层的「行动」页有「重新生成本轮变量」。填写可选依据，调用酒馆当前模型；先看变化与候选补丁，再点确认保存。保存会更新同楼变量和正文中的 UpdateVariable，保留故事正文。它针对整轮失败的更新；已经成功保存的资源漏记仍用下方补记校正。
2. **能力卡**：初始能力介绍、能力新获得或进化时，AI 应在对应段落后输出获得卡；获得卡默认展开。卡片直接读取同楼变量，晚到的变量或手动修复完成后会原地刷新。
3. **人物连续性**：重要人物出现后看「人物」页。身份、外貌、性格、动机、说话方式、知识、关系经历和近况可查阅、编辑；换场景后人物仍保留。可将人物整理为世界书档案，再在潮镜中编辑保存。
4. **生成角色／位面**：在「潮镜」填写构想，选择是否参考当前情境。生成后编辑完整 JSON 字段，预览满意再保存。存放于当前聊天绑定的世界书；未绑定时创建本局潮镜世界书。生成的设定条目关闭，由 EJS 读取明确的世界书与条目名。进入位面、人物在场或最近正文提及时调用；不会把全部条目名称与正文常驻发送。生成和保存不会自动启程或安排角色出场。
5. **回访**：保存位面后，游玩时提及其名称；旅行沿用档案中的位面 ID。再次前往应继续原设定。角色以档案中的 ID 收录，后续在变量里更新最新经历。

## 验证边界

浏览器交互验证使用真实构建产物、模拟的酒馆接口和 AI 返回值，没有在玩家聊天中调用模型或写入世界书。真正模型能否稳定遵循触发格式、角色描写是否自然、当前安装的 EJS 扩展实际联动效果，仍需导入后的游玩测试。

0.2.0 已导入的卡仍带有旧脚本与世界书；需要使用 0.3.0 卡包。现有状态结构有默认补全并保留旧命令格式兼容，但本轮没有替玩家迁移旧聊天。
