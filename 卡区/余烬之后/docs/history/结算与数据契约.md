# 结算与数据契约草案

本文件是独立 MVU/schema 的设计依据。schema、MVU 更新保护、EJS 路由与测试规则下的纯结算闭环已建立，具体字段与当前边界见 README.md。酒馆提交器、开放世界能力目录与正式平衡尚未实现。

## 权限与数据边界

| 数据 | 写入者 | 说明 |
| --- | --- | --- |
| 玩家已声明行动 | 玩家输入，模型解析 | 解析不得附加未声明的自杀、攻击、能力使用或对话 |
| 敌方行动提案、场景变化提案 | 模型 | 受已登记实体、技能、条件与资源约束 |
| 生命、消耗、状态、伤害、死亡、复苏 | 结算脚本 | AI 的 MVU 更新不能覆盖这些结果 |
| 能力与实体的数值定义 | 规则目录与校验后的创建流程 | 不接受直接执行的模型代码或任意公式字符串 |
| 观察、人物对白、事件描述 | 模型 | 与已结算事实一致，区分事实、推测与未知 |
| 已结算事件、状态快照、分支信息 | 结算脚本 | 用于恢复、回退、重试和防止重复处理 |

下划线字段可表达模型只读约定，但真正的写入保护要在更新流程中执行。仅在世界书中声明“只读”不足以保证正确性。

## 建议的数据域

- 存档：版本、会话标识、分支标识、当前事件编号。
- 开局档案：默认或自定义模式、玩家已确认的身份字段、原世界、既往经历、初始能力规格、机缘事件和初始化完成标志。
- 世界：当前位置、已登记地点、统一时间刻度与显示历法、正在推进的事件。
- 主角：身体阶段、生命与资源、状态、持有或遗留物品、已获得能力。
- 能力目录：来源、机制标识、触发条件、效果操作、参数、成长记录。
- 实体目录：生物、人物、危险源与其合法行动；隐藏参数与玩家可见信息分开。
- 死亡记录：死亡前快照引用、来源、机制、时间、关联能力与重构记录。
- 复苏：阶段、锚点引用、预计完成时间、恢复项目、携带物转移记录。
- 结算记录：输入状态版本、合法行动、随机结果、实际变化与输出版本。
- 见闻：已观察事实、信息来源、知情角色和更新时间。

实体、能力、物品使用稳定编号作为主键，名称作为可变显示字段。记录用编号映射保存，不能因改名产生第二份能力或复制物品。

默认主角与自定义角色最终转换成同一种运行时结构。自定义原有能力需在进入相应结算前完成效果映射；不因为选择自定义而自动额外发放起源能力。初始化只执行一次，重新打开封面不覆盖已经发生的经历。

## 一次行动的处理

1. 从当前分支读取权威状态与已登记实体。
2. 将玩家声明解析为行动提案；模型可生成符合角色已知信息的敌方提案。
3. 校验目标、距离或接触条件、行动资格、资源和能力参数。
4. 结算实际变化；需要随机时由脚本取样并保存结果，模型不得改骰。
5. 在提交前验证状态版本仍然一致，原子保存事件及新状态。
6. 将结果与玩家可知的信息交给叙事请求，正文据此展开。

若出现尚未支持的机制，保留待解析提案，不消耗资源、不直接宣告胜负。补充合法规则后继续同一次行动。叙事生成失败时保留已结算结果，重试叙事不得再次结算。

模型仍然承担开放世界的语义解释；脚本不能凭空判定所有自然语言。严谨性的边界是已登记机制、可验证条件和确定的结算顺序。

## 死亡与复苏的事务边界

死亡确认先产生唯一事件，再产生能力授予记录和重构计划。能力档案引用原死亡事件；同一事件被重新渲染、收到重复回调或发生叙事重试时，只读取原结果。

复苏完成统一处理身体恢复、时间推进、能力可用性和物品转移，不让界面分别写入半完成状态。关闭再打开界面不会推进世界时间。

## 酒馆中的历史与回退

消息楼层快照用于查看历史，历史界面不提交新操作。重新生成必须区分“重写同一结果的正文”与“从之前状态建立新分支”；两者不能共用不明确的 latest 状态。

切换聊天时清理监听与当前事务，载入目标聊天的状态。并发提交需要版本检查，重复点击不会重复扣费。事件去重标识必须包含分支，不能因为旧分支处理过同名事件而吞掉新分支行动。

## 首轮必须验证的行为

- 非致死伤害不授予死亡能力；致死事件恰好授予一次。
- 已适应的相同机制按既有规则防护，不能靠修改攻击名称绕过。
- 复合伤害保留来源与机制，不能把所有后果归给最后出现的名词。
- 重构期间时间推进一次，复苏后生命、位置与物品保持一致。
- 重复点击、重复事件回调、界面重载和叙事重试不复制能力或物品。
- 新聊天、回退与分支重生成相互隔离；历史楼层展示历史快照。
- 模型对权威数值的直接更新被拒绝或剔除，同时保留合法叙事更新。
- 未知技能、资源不足、过期状态版本不造成部分写入。

以上是完整结算的验收目标。当前已验证结构解析、模型字段保护、位面路由，以及测试规则下的死亡奖励去重、直接伤害、能力防护与释放、复苏时间推进、期限与掉落保留。酒馆持久化、并发提交、回退与历史分支创建尚未实现，不能把内核测试视为酒馆端到端验证。
