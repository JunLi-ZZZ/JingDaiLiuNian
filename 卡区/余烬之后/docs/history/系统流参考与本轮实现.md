# 系统流参考与本轮实现

2026-09-15。参考当前 `src/系统流/schema.ts`、`界面/动物园/types.ts` 和 `store.ts`，并核对两份系统流交接。没有修改系统流或复制其界面样式。

## 借鉴结果

| 系统流中的结构 | 新卡处理 |
| --- | --- |
| 通用状态与动物园数据分开 | 保持新卡的通用实体/能力/物品结构；玩法内容按实际使用增加。不提前加入动物园字段，也不建立空白DLC容器 |
| 任务的要求、进度、状态、奖励和限时 | 增加 `_任务`，目标支持数值进度；期限用统一时间刻度；模型只能提交任务变化提案 |
| 兽员以个体区分，同种可有多只 | 实体保持稳定ID，增加种族ID；同种同名生物可以共存，改名不改变引用 |
| 兽形与兽娘两种描述 | 扩展为通用形态记录，可保存人形、兽形、雾态或其他形态，不强制兽娘；形态描述本身不授予能力 |
| 立绘字段 | 每种形态有可选图片字符串；当前不生成、不下载图片 |
| 概率、消耗、保底由程序负责 | 使用纯结算模块处理已支持的直接伤害、能力与复苏；随机概率玩法本轮未加入 |
| 独立store和本地持久化 | 内核接受显式会话快照，不使用浏览器全局localStorage保存玩法状态 |

旧动物园仍是 mock 原型，不能把可点击界面等同于正式 MVU 接入。它的抽取函数存在先扣费后检查类别/孵化容量的顺序；新卡采用完整校验、副本运算、成功返回的方式，失败不留下部分变更。

## 本轮结算范围

`engine.ts` 提供 `startSession`、`applyCommand`、`validateSession` 和 `localTime`。

- 开局支持默认/自定义身份；自定义未填的经历与身份不继承默认主角。开局快照从已确认取得起源涅槃之后开始，不生成先前死亡记录。
- 直接伤害记录来源、机制、作用条件和实际损伤，复合攻击按给定顺序结算。首次导致生命归零的原因标记为直接死因，其后原因不再执行。
- 主角死亡后登记能力并进入重构。测试能力是对应机制的被动转移与主动储能释放；更强同类攻击导致再次死亡时强化同一能力。
- 时间推进更新任务期限和复苏可用状态。复苏恢复生命与锚点位置，保留人物交往、世界事件文本与现场掉落。
- 普通随身物品留在死亡地点，绑定物品保留；同一物品实例不复制。测试规则不支持嵌套容器。
- 相同事件ID与相同请求返回已有结果；同ID不同请求、错误分支和过期状态拒绝。完整会话JSON往返可保留去重记录。

`trial-1` 是内部验证规则，不是正式游戏平衡：只登记电击、热损伤、冲撞三类直接伤害；复苏耗时600起源秒；适应按该次致死攻击强度建立转换上限。每次转换多余能量散逸，储能有容量，主动释放消耗当前全部储能。它用来验证“获得有用途的新能力”，不代表最终所有能力都做成吸收反击。

引擎目前只接受代码侧已登记的实体和可信指令。伤害数值仍由调用者提供，尚未完成敌人技能目录、行动经济、距离、命中和模型提案校验，因此不能声称任意AI文本已经能够严谨战斗。当前位面开局仅支持六个已登记预设位面，自定义人物原有技能仍需后续定义流程接入。

时间推进只处理已登记期限，不凭空生成世界事件。锚点失效时保留重构状态并报错，备用锚点机制待定。状态效果、嵌套容器、未知被动能力在本切片中明确拒绝，不静默忽略。

## 模块、存档和接入边界

当前数据只有本卡需要的通用字段；任务和形态默认为空记录。若以后加入一个全新玩法，其独立数据应在选择后初始化，卸载规则需在接入该玩法时明确；本轮没有建立合集切换。

`death_adaptation_runtime` 已作为纯内核会话的一部分保存规则快照和事件账本，位于stat_data之外。还没有酒馆持久化提交器、分支创建/回退流程和历史页面写入保护；不得把纯函数的状态版本检查当成跨窗口原子锁。

新卡独立构建额外输出 `build/0.1.0/核心/engine.js` 模块，尚未自动挂载到酒馆。演示运行 `npm run demo`，结果保存在 `结算演示.md`。现阶段继续保持不提交、不推送、不升版，也不改其他卡构建配置。
