# 开局复查记录 · 2026-09-18

本轮范围：独立封面、自定义开局、开场白与初始存档衔接，以及既有核心玩法回归。未调用其他卡的构建、升版、同步或发布入口。

## 确认的问题与原因

1. 旧卡首楼与正文均使用 `<EmbersPanel/>`。状态栏入口依初始化状态切换封面和状态栏，因此两者实际上没有分开。
2. 旧“启程”回调只调用 `initializeOpening` 保存数据，没有创建剧情消息，也没有请求或提供开场白。点击后只有面板是代码行为，不是模型生成质量问题。
3. 旧浏览器测试以“显示角色标题、变量已保存”为成功标准，没有要求出现可接续的剧情正文。这使技术检查通过与实际可玩之间产生缺口。
4. 镜待流年的 `StoryPanel.vue` 实际生成的是世界观背景条目并写入共享世界书，不是玩家当前聊天的开场白。直接复用会把“选开局”变成“修改整张卡的世界书”。
5. 旧开局把主角、时钟和锚点固定在星见市。新增自定义开局必须让三者一起使用所选位面和地点。
6. 旧文档仍有“未挂载”“未来清单”等过时说明，已按当前独立打包流程更正。

复现：对旧PNG检查首楼标记，以及旧前端是否调用创建消息接口，确认首楼为状态栏标记、启程函数没有创建消息。最小复现断言失败，错误指向共用入口与缺失开场白。

## 修复后的行为

- `<EmbersCover/>` 与 `<EmbersPanel/>` 分别加载独立构建的封面和状态栏。状态栏包不再携带封面原头像。
- 默认开场无需AI，提供位面潮汐后的现场、伴生之灵初次说明和工作人员的询问，把下一步交给玩家。
- 自定义开局支持预设位面和原创／同人世界，手写构想或大纲、AI整理大纲、AI生成开场白、编辑正文后确认。
- 草稿生成显式携带本局角色、所选世界资料和开局约束；不依赖尚未确定的当前位面，不修改共享世界书，不提前初始化。
- 确认时用一次 `createChatMessages` 把开场白和完整MVU快照放到新楼层，封面保持未初始化记录。已有开局标记用于去重；历史、切换聊天或封面变化时拒绝重建。
- 新剧情楼层携带数值账本，后续结算沿用原事务与保护机制。
