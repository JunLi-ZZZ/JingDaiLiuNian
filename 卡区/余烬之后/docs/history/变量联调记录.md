# 2026-09-19：变量更新与独立版本联调

## 故障证据

原测试聊天在17:50连续两次输出空JSONPatch。第二次Analysis把NPC反应与环境变化当成“没有时间跳跃，因此无更新”。各楼层存档也原样继承，状态栏显示与存档一致。

酒馆实际绑定的无版本世界书“余烬之后”仍含早期规则和旧的变量列表，和本地包不同。初始打包器还把所有条目位置固定为角色定义前，忽略了条目独立配置。这三处共同导致修改后的规则难以可靠进入测试。

## 本次变更

- 参照镜待流年的字段type/check组织，逐项写明时间、场景、见闻、关系和外界事件的更新条件。
- 叙事.本轮时间提供起算起源秒和经过本地秒。MVU结束事件接纳该记录，经内核换算、结算、保存；不需要手动确认普通叙事耗时。
- 时间基准与快照绑定，重复解析和继承旧记录不重复累计；战斗自身耗时仍由动作结算。
- 修正外界事件的字段说明为schema中的对象结构。
- 独立版本0.1.1：卡名和世界书名均为“余烬之后 v0.1.1”，EJS getwi明确指定本版本世界书。旧卡与旧世界书保留。
- 按写卡知识库设置世界观在角色定义前、具体资料在角色定义后；D0 system依次为当前变量100、规则控制器200、输出格式300。打包器实际保留这些位置。

## 实际验证

通过Codex内置浏览器导入0.1.1构建，独立新建聊天“余烬之后 v0.1.1 - 2026-09-19@13h16m01s154ms”。启用本卡正则和脚本，导入并确认主世界书为0.1.1，实际API读回D0的深度与顺序正确。使用用户原有API和预设，通过封面及酒馆输入框正常生成：

1. 开场生成实际更新块，场景和人物互动写入存档；模型判定开场耗时0。
2. 普通询问面馆推荐：模型输出本地180秒，实际存档起源时间变为180，状态栏17:53:00，场景、见闻和互动有变化。
3. 原地等两分钟：模型输出起算180、经过120，实际存档时间变为300，外界事件的进展与结束状态写入。

联调中纠正的外界事件结构已同步到新版测试世界书与最终PNG。纠正之前生成的旧楼层保留原状，不重写生成历史。

在当前真实MVU的存档副本上解析完整事件及60秒推进：300→360；再解析同一指令仍为360。事件的位面、地点、进展、因果依据和状态全部保留。解析前后真实聊天存档完全一致，此项是插件解析验证而非新的AI回合。

刷新酒馆并从最近聊天重新打开该测试聊天后，绑定世界书仍为“余烬之后 v0.1.1”，存档起源时间保持300秒，最新状态栏显示17:55:00。计时事件仍仅有narrative-time-0、narrative-time-1两条，没有因重新加载而重复累计。“本轮变化”显示游戏时间17:53:00→17:55:00、场景和外界事件三项变化。

离线回归包含普通对话、重复解析、重抽分叉、下一轮继承、位面倍率、旧账本兼容、战斗6秒、重构完成、新旧提案版本、世界书位置映射、EJS版本隔离及升版输入校验。TypeScript与ESLint检查通过。头像原始图像块和PNG载荷回读校验通过。

本次验证覆盖变量更新和发布绑定，并不表示开放世界的移动、物品、任务等未实现数值操作已经可结算；玩法边界继续以README为准。模型对叙事耗时的估计仍属于语义判断，脚本负责换算和一致性。
