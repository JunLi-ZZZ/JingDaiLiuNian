# 0.1.2–0.1.3 重构与联调记录

日期：2026-09-19。范围：本卡目录。镜待流年作为只读参照，本轮没有执行根构建、根升版或推送。

## 背景与条目

- 起源之母与初微统一；虚海与起源之海为同一片海的不同称呼。保留共享的主世界、诸位面、跨界路线与开放世界生成。
- 核心总纲、故事基调、种核传承、涅槃、人物、庭院、位面、控制器和变量分别归档。当前包共23项世界书条目。
- 已有位面详细资料保持关闭，由EJS按当前位面加载。未知世界保存本局简介，抵达后读取；模型当轮变量视图不包含全部位面文件名。
- 初微、艾斯特瑞亚、星界庭院的详细资料按传承状态和剧情调用。初微授予的传承可由机缘获得，角色身份可自定义。
- 单独的玩家身份与称谓条目已移除。变量文本将酒馆宏替换后的用户名称映射到本局档案。

## 运行机制

- 封面建立数值快照，首次正文全量填写叙事资料；`叙事.首次资料完成`独立控制首次与日常规则。
- 日常耗时与已发生操作写入当轮结算，脚本计算数值。重复解析同一快照不重复计时或随机掷骰。
- 起源涅槃作为初始被动能力入册。环境损伤、死亡、适应、重构、复苏、同机制转移与储能使用组成可执行链路。
- 见闻可合并、修订、删除；常用记录至多24项，较早记录归档。模型每轮视图至多10项见闻，界面可翻阅旧页。
- 状态栏默认折叠，展开后用一组页签组织内容，行动与变量变化归入同一面板。

## 酒馆真实联调

在`http://127.0.0.1:8000/`导入本轮0.1.2首个构建，绑定世界书为`余烬之后 v0.1.2`，旧版卡和旧聊天保留。

已确认：

1. MVU、EJS、本卡变量结构与初始化五项检测全部就绪。
2. 独立封面能够进入角色与开局设置页；设置页不重复显示环境检测。
3. 默认开局要求作为用户楼层发送，AI成功生成旧渡口第一幕，包含许灯求援、伴生灵与起源涅槃。
4. 首轮JSONPatch全量填写叙事资料，首次标记变为true；时间从17:50:00变为17:50:15，面板显示10项变化。
5. 第二轮使用救援过程中的断裂电缆事故测试致命损伤。AI输出300点电击，但同时附加了提前复苏操作。运行日志明确报出“尚未到复苏时间”，整批状态正确回退，避免部分写入。

由真实失败补充的修订：

- 行动规则明确：致命伤自动进入庭院并启动重构；revive表示达到完成起源秒后的身体归来。跨越全部阶段时，600秒等待放在致命伤之后。
- 错误原因由MVU外层字段改为schema内的`_更新错误`，避免保存时丢失；状态栏读取该字段，模型视图提供上轮反馈，成功更新后清空。
- 当轮视图包含伴生灵稳定ID，关系更新沿用该ID。
- 新增回归覆盖提前复苏失败、修正后的分阶段复苏以及同轮顺序计时。

用户随后导入修订后的0.1.2并新建聊天。通过只读检查确认新阶段规则与`_更新错误`字段已加载。本次浏览器调试没有通过CDP改写聊天或变量；副本解析检查后确认原楼层数据未变。

真实复测结果：

- 自定义角色林澈／女性保存成功，首轮初始化完成，起源时刻推进至15秒。
- 救援中的致命电击输出exposure 300：生命0、重构中、电荷转移能力已生成，开始时刻25秒，完成时刻625秒。
- 等待完整十分钟后输出revive：时刻625秒、生命100、存活、复苏记录清空，外界剧情继续。
- 在真实MVU上用存档副本重放提前复苏，返回“尚未到复苏时间”，原楼层数据未变。
- 状态栏默认折叠、展开后的统一分页、重构提示、战斗数值与能力页已检查。

主动运用复测发现第二个问题：模型把吸收与供电都写成amount为0的channel；严格MVU输入校验筛掉行动批次，其他字段仍提交，导致时间已前进而储能保持0。0.1.3将时间与行动接收层改为保留原始值，在本卡提交层统一严格校验，失败时整批回退并提供错误反馈；规则明确吸收采用exposure、消耗采用channel。新增接收层回归确认无效操作保持可见并被整体拒绝，时间不单独推进。

**0.1.3最终卡包已生成，尚未进行真实AI复测。** 跨界测试的浏览器请求随后超时，是否发送成功无法确认；浏览器控制恢复尝试也超时，因此没有重复发送。未知世界旅行仍只有离线回归证据。最新文件为`release/0.1.3/余烬之后-0.1.3-dev.png`。后续打开、导入和替换角色卡由用户操作。
