# 余烬之后：新卡设计草案

更新：2026-09-16。正式定名《余烬之后》，开发文件夹已同名迁移。

当前阶段已有独立 schema、MVU 注册与更新保护、位面副本、EJS 条目清单、内部测试规则下的死亡适应与攻防结算、开局/状态栏，以及使用用户头像生成的开发 PNG 包。开局接入已通过模拟 MVU 验证，真实酒馆和正式战斗提交仍待联调。实现范围和验证见 README.md。文中的建议参数不代表用户已经确认。

## 已确定的方向

- 主角死亡后，根据致死事物的特点获得新能力；能力可以用于攻击、移动、感知或防御，不局限于抗性。
- 世界继续向前，主角在同一条世界时间线上复苏。旁人的记忆、事件进展与已经发生的后果保留。
- 关键数值由脚本结算，模型依据结算结果叙事。
- 新卡独立设计 MVU/schema 和前端风格。生物、技能、物品小卡片可按需要借鉴镜待流年的交互。
- 当前制作独立新卡；合集封面、主题切换、跨卡存档迁移留到后续。
- 位面参考并复用镜待流年，按新卡身世和权能调整副本；构建、版本和未来打包发布独立，不能影响其他卡。
- 保留起源之海、起源之母与伴生之灵组成的起源体系，重新打磨其职责与故事。
- 玩家可以自定义角色，也可以直接使用默认主角。起源体系不规定玩家必须具有某种血统或前世。
- 能力通过机缘获得，具体机缘情节仍属设计建议；传承描述获得权能后的联系，不反推玩家出生身份。

## 核心体验

探索和人物交往构成日常。危险来自世界既有的生物、势力、环境与规则。玩家选择行动，结算确定后果；死亡留下经历和新能力，复苏后的玩家重新进入已经发生变化的世界。

游戏不以凑齐死法为强制目标。逃脱、协商、求援、观察、准备和成功生还都有推进价值。死亡也不自动追加羞辱、关系崩坏或随机失物作为惩罚；后果来自已发生的事件与明确规则。

“数值严谨”首先指相同条件得出相同结果、资源变化有依据、能力效果可检查，而不是把所有生活行为都变成掷骰。

## 主角与开局

开局提供“使用默认主角”和“自定义角色”两个入口，进入同一套玩法。默认主角必须有完整可用的初始档案和处境，玩家无需填表即可开始；允许在开始前修改。姓名、性别、外貌等具体默认值仍待拟定，不以玩家没有填写为由要求补齐所有字段。

自定义角色可填写姓名、性别、种族、外貌、原世界、经历与原有能力。只应用玩家明确选择的默认内容，不静默添加恋爱关系、固定性格、前世、失忆或死亡经历。空缺信息中不影响开局的部分可以留白。

原有能力保留设定表达，涉及结算的部分转换成明确效果与参数。跨世界角色无需改成凡人，但不能把“无敌”等自然语言直接作为跳过所有结算的规则。自由度与数值严谨通过明确角色初始规格相容，不靠暗中削弱角色。

建议默认机缘：位面潮汐令一枚承载起源涅槃的种核进入当前世界；主角在接触事件中与之建立联系，伴生之灵随之苏醒。种核名称、接触地点和事件细节都是暂拟。该事件可以发生在现代生活、遗迹探索或其他开局中，不要求主角先死一次，也不额外强塞穿越剧情。

获得核心天赋时只开启“死亡后重构并生成对应能力”的机制。首次死亡尚未发生时，不赠送长生、空间旅行或多种死亡所得能力。若玩家选用有既往死亡经历的开局，则逐项登记来源与能力。

起源之母作为权能源头存在，后续是否见面、是否发展师承或亲密关系由经历推进；获得传承不等于已经认识她、认定她为母亲或愿意服从她。伴生之灵同样从具体相遇建立关系。

## 能力生成建议

记录“来源—机制—作用条件”，例如：雷兽的放电器官—电流穿过躯体—接触湿润地面。复苏能力从这条因果链提取特性，不能直接继承来源的全部力量。

建议一次有效死亡生成一个能力档案。档案可以同时包含针对该死因的适应效果与可主动使用的衍生效果，两者使用同一能力来源记录。是否永久被动、是否占用容量，尚未定案；不预设卡槽制。

| 致死机制 | 能力方向示意 | 必须明确的规则边界 |
| --- | --- | --- |
| 电击 | 电荷转移：将进入身体的电流导向接触的导体，或暂存后释放 | 接触条件、转移额度、储量、释放代价；不扩展为所有能量免疫 |
| 冲撞 | 冲量偏折：改变作用于身体的部分冲量方向 | 可作用强度、方向、触发窗口；不自动获得位面跃迁 |
| 缺氧 | 闭息循环：在缺氧时延长身体维持活动的时间 | 可维持时长、恢复条件；与水压、寒冷、毒性分别结算 |
| 热损伤 | 热量收纳：吸收一定范围的外来热量并用于释放 | 吸收速率、储热上限、释放方式；缺氧并不属于热损伤 |
| 空间切割 | 空间锚定：短时保持身体所在区域的空间连续 | 有效范围、持续时间、来源强度；长程旅行另行定义 |

这些是方向示意，不是已确定的开局能力或正式数值。

### 同类死亡与成长

建议重复遭遇同一已适应机制时，由现有能力先参与判定。条件相同且适应已经足以阻断致死过程，应当生还，不能换一个攻击名称就绕过适应。

更强来源或复合机制仍可能导致死亡。建议这种死亡扩展已有能力的额度或分支；新增机制才优先产生新的能力档案。不按死亡次数线性叠加奖励，也不凭模型主观判断“刷取动机”剥夺结果。

须在数值设计阶段决定：适应对首次死因的保证是自动生效，还是提供需要玩家主动使用的解法。两者不可在叙事中混用。

## 死亡与复苏建议

状态流转：存活 → 死亡已确认 → 重构中 → 复苏完成。

确认死亡时，冻结该事件的因果记录、当时能力与资源快照，建立唯一死亡事件编号。能力生成和复苏分别关联该编号，重复触发不得重复奖励。

建议通过已登记锚点复苏；复苏耗时使用游戏世界时间，不要求玩家现实等待。具体时间、初始锚点和锚点更换条件待定。外界事件按相同时间增量推进，不能随意让重要人物在每次复苏时恰好遇难。

必须明确身体、衣物、携带物与掉落物的处理。建议重构恢复身体，普通携带物留在死亡现场；只有显式绑定的物品随复苏转移。被绑定物品转移后，现场原物也须移除，避免复制。此项属于待讨论的游戏规则。

重构完成后只存在一个可行动的主角身体。旧身体如何消散、遗留物如何呈现，须在正式设定中统一。若锚点失效，应使用事先定义的备用规则，不临时宣布永久死亡或自动赠送新位面。

## 世界与角色

先设计一个足够承载探索、日常和数类危险的起始地区。多元世界可提供后续空间，第一版不要求穷举所有位面。

角色复用按人物检查：保留有辨识度的性格、习惯、欲望与边界，重新核对身份、力量、既往经历和玩家关系。避免照搬超高位保护者后，又在每次死亡时临时解释其为何不出手。

伴生之灵可以解释已知能力、记录旅行、与玩家建立关系；她不能替玩家表达感受、自动替玩家使用能力，或预先知道所有危险的答案。角色性格应包含自己的兴趣、判断与分歧，不只承担状态栏播报。

## 前端方向建议

以“归来者的旅行档案”为界面主题。初步采用墨蓝、骨白与少量余烬色，强调清晰的能力结构与经历记录；正式视觉风格仍可调整。

- 概览：身体状态、当前位置、世界时间、资源与正在生效的状态。
- 能力：生效条件、主动效果、代价、当前额度和来源死亡记录。
- 行囊：装备、物品、材料；明确在身、存放、遗留的位置。
- 见闻：生物、人物和地点；区分已观察信息与未知信息。
- 归来记录：死亡原因、获得的能力、复苏耗时及期间已知事件。

小卡片继承“正文可点开查看详情”的交互思路。视觉样式、字段与数据访问重新适配；不整套导入镜待流年状态栏，也不继承其手机、情缘或品阶字段。

玩家界面只显示已经知道的敌人信息；脚本使用的隐藏参数独立保存。所有历史卡片显示对应楼层的快照，只有当前有效分支允许提交操作。

## 实现顺序

1. 收敛起源背景、初始处境、适应保证与复苏规则。
2. 建立独立 schema 与纯结算模块；先验证死亡、能力获得、复苏和重复事件处理。
3. 接入模型行动提案、脚本结算、结果叙事，跑通一个遭遇。
4. 根据实际数据制作独立状态栏与小卡片，再扩充起始地区和人物。
5. 完成酒馆内开局、存档、切楼、重试与回退验证后，打包为正式角色卡。

当前配套的世界书草案与数据契约供下一步实现使用，不代表上述步骤已经完成。
