# 03 · 协作、验证与回退

## 分工与回交

Fable5先审当前实际发送给模型的文本、改手写世界书、完善角色/世界资料与生成提示词。Codex负责schema/解析/数值执行器/前端的配套修改与联调。用户可随时调整分工。此处只是协作约定，不应限制用户已授权的工作。

两边先读对方回交再改同一文件。Fable5写入docs/handoff/04-Fable5回交.md，注明文件、最终改动、文本要求的字段/行为及尚待代码实现。Codex接续时核对该文件与实际源码，不依靠版本号推测发生了什么。

不需要通过Slack、邮件或自动控制另一代理进程交接。把HANDOFF.md入口交给用户在VSCode中的Claude Code即可。当前没有调用或发送指令给Fable5。

## 建议的一轮工作

1. 读截图待办，明确哪一层失败以及需要取得的证据。
2. 查看最终世界书组合与状态投影，拟定通用文本方案。
3. 修改手写源，记录哪些字段或协议需要代码同步。
4. 运行generate，检查派生文本和EJS路径；生成文件被覆盖的部分应回到源修改。
5. 验证一份最小完整输出经MVU解析和本卡结算后的状态，并验证失败情形。
6. 再扩大为首次、日常、死亡、普通能力、开放进化、旅行、工坊场景。
7. 更新回交和验收记录。完成代码配套后再独立升版与打包，用户导入并体验。

## 命令

在卡片目录执行：

- npm run generate
- npm run typecheck
- npm run lint
- npm test
- node tests/reproduce-feedback.cjs
- npm run build
- npm run preview

浏览器检查需Playwright可用。本机已验证：
powershell环境变量 DEATH_ADAPTATION_PLAYWRIGHT=C:/Users/lenovo/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright
随后 npm run test:ui（3组浏览器脚本）。脚本用Edge headless模拟接口，不调用付费模型，不写用户真实聊天。

npm run pack会构建并写release/当前版本。为了保留历史0.5.0，实际发布下一版先运行本卡npm run bump -- 新版本，再pack。不是根目录的bump_version.mjs，也不是镜待流年的release脚本。

所有新增日志放tests/logs/，当前浏览器证据仍在build/verification/（已有子目录）。根目录不再放临时log或测试报告。测试示例不是世界书正文，不要将样例中的人物和能力作为通用规则注入。

## 备份与回退

备份根：
E:/st-main/tavern_helper_template-main/_local_backups/余烬之后_交接前_0.5.0_20260922-093116

包含余烬之后/完整副本、files.sha256.json和backup.json。514文件均已SHA-256核对。备份创建于移动文件之前，不包括本轮后来新增交接材料。

需要回退时：
1. 先将协作后的整个卡目录复制到新的带时间戳备份，记录哈希，保留Fable5和Codex成果。
2. 核对源和目标的绝对路径都只指向余烬之后及指定备份目录；确认要恢复的是哪次存档。
3. 在用户授权恢复后，用单一PowerShell流程将当前目录移到单独保留位置，再把完整备份复制回卡区/余烬之后。避免直接合并复制留下新旧两套源码。
4. 按files.sha256.json逐项验证恢复结果，再运行该存档对应的命令。
5. 其他卡、根配置、环境密钥、真实酒馆聊天与世界书都不在本次回退范围。

用户当前授权的是创建存档和整理交接，不是立即执行回退。用户原头像保存在assets/头像.png，内容哈希与备份头像一致。
