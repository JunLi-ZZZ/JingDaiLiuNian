# 给 Claude：虚海重构、多能力开局与人物互动

日期：2026-09-23。用户已确认本轮顺序：**Codex先修EJS并交接 → Claude编写世界书文本 → Codex接回实现封面选择、初始化、条件加载和计算机制。**

本文是作者协作文档，不进入酒馆提示词。最新用户要求高于旧版交接与旧世界书。当前可运行版本0.5.4只修EJS，仍使用旧起源涅槃开局；下面是下一版的创作任务，不能把文字完成等同于程序已支持。

## 1. 创作目标

《余烬之后》仍以虚海与多元位面为共同舞台。体验由细腻的人物交流、亲近与陪伴、世界探索，以及紧张有表现力的战斗共同构成。数值承担需要计算的结果，让对白、日常、情感和关系变化自然展开。用户明确偏好：主要角色阵容以有魅力、值得相处的优秀女性为主，各人具有鲜明的生活、愿望、性情与行动逻辑；这是一项创作取向，不是所有位面居民的性别定律。

规则宜短而清楚，正面说明角色如何行动、模型如何创作。技术ID、交接限制、纠错历史属于开发文档。已发生的经历和关系是之后发展的基础；玩家姓名、性别沿用已解析的本局档案，玩家代称和操控范围继续与酒馆预设协作。

## 2. 用户已经确认的世界背景

以下因果骨架需要写成清晰、可扩展的背景条目。用语统一为**起源之神初微、终末之神末墟、虚海之灵**。

1. 虚海是众位面的起源，其他位面由虚海衍生。各位面可以具有不同文明、力量体系和演变路径，预设目录之外的世界仍可存在与探索。
2. 初微与末墟是世界初诞时应运而生的两位原初之神，古老程度与力量仅次于虚海之灵。两者关系亲如姐妹。
3. 随着世界发展，即使虚海自身也经历起源之力削弱、终末之力繁盛的趋势，最终寂灭成为正在逼近的深层问题。
4. 虚海之灵尚未形成成熟灵智，并处于沉睡之中。其自救带有本能与幼稚的误判：试图使用本源力量重伤末墟，以为这样就能阻止寂灭。
5. 初微不会坐视好姐妹遭到重伤，站到末墟一边，与虚海之灵的自救力量发生冲突。这里的“两方”是虚海之灵一方，与初微、末墟一方。
6. 冲突中，虚海之灵的本源力量崩碎，形成若干原初神器。当前先创作六件，外观类别为不同种类的武器。
7. 神器等待有缘人收集，全部汇合可合为虚海本源，通向重塑世界的可能。它构成可逐渐发现的远景与长线，并非每个开局立即接取的唯一任务。

背景需要补足“力量变化—错误自救—冲突—本源碎裂—重塑契机”之间的因果，使故事能据此展开。具体的神器散落过程、为何凝成武器、重塑的条件与代价可由Claude创作成连贯草稿，在回交中标出新增决定。保持“六件是本次创作规模”的含义，避免把整个世界的可能性写成永久只有六件或只允许一种收集顺序。

**三者的详细人设本轮留空给用户后续通过潮镜生成。** 世界背景只交代身份、关系及历史作用；外貌、年龄表现、性格细节、说话风格、喜好、完整个人经历放未来独立角色条目。虚海之灵尚未成熟和沉睡是既定背景事实，不等于已经完成其整个人设。

旧版“主角必为两母力量交融所生”“人人开局已有种核/终焉眷引/越界”“车祸后必在归泊庭重构”都属于旧玩法设定，不构成新共同背景。如何保留旧路线的获得机缘与专属空间，放起源涅槃模块中衔接；不得由一次背景改写把已有聊天事实追溯改掉。

## 4. 初始能力选项与开放成长

需要准备以下可选路线的文本。下列是首批目录，不是未来能力全集，也不是角色一生只能持有一种能力的限制。各能力获得后沿用通用能力档案、品阶、等级、熟练度与开放进化。

| 选项 | 已确认的方向 | 本轮需要交付的文字 |
| --- | --- | --- |
| 起源涅槃 | 保留死亡后复苏并从死因获得适应的路线；世界继续推进 | 整理现有玩法，在新虚海背景中说明能力作用与获得方式；专属奖励各自成条 |
| 吞噬进化 | 吸收/吞噬后提取能力或特质，并能融合、演变 | 来源、承载、消化/吸收、形成能力的过程，以及足够开放的成长逻辑 |
| 合成进化 | 将已有能力等有效素材组合，生成与素材及实际处境有关的新结果 | 参与素材、结合依据、结果生成、代价与素材去向；候选方案供确认 |
| 抽卡 | 用户早先提出的武器/角色等塔罗式抽取与对决方向 | 作为已有想法纳入本轮候选稿；卡池、抽取代价和角色卡实际形态标为待定，不假定商城/付费/固定保底已确定 |
| 不选初始能力 | 可以不接受额外的开局能力 | 自然的普通起点；学习与之后获得能力仍开放 |
| 随机能力 | 自由生成一项适合所选起点的能力 | 生成所需的通用质量要求、作用/条件/代价/成长信息；生成结果可预览、调整 |
| 自定义能力 | 玩家描述构想，AI补全为可用能力 | 尊重构想，整理为明确的能力定义，留下可扩展的实际作用 |

随机能力应允许生成菜单之外的能力；默认选项与自定义是准备流程，AI正式游玩时主要收到**本局已经选定的能力和实际状态**。未选中的路线无需每轮一起塞进提示词。是否允许初始多选、默认预选哪个选项以及抽卡的完整数值方案尚未由用户定案，回交列为待定即可。

进化仍采用既定交互：满足条件后出现按钮，根据现有能力、使用经历、材料和处境生成候选，玩家可补充意图、重拟与确认。成长结果不收窄为固定几个方向或固定等级上限。AI创作新效果与程序是否能执行该效果分开描述；特殊作用有程序缺口就记录到技术回交。

吞噬与合成可能共享某些“产出能力”步骤，但它们的作用对象、来源和付出应各自清楚。素材保留/消耗、继承程度、失败后果等需要可核对的文本语义，供脚本实现原子结算。具体数值公式与API名称由Codex接回后制定，不在写作时猜一套操作命令。

## 5. 交流、女性角色与战斗的关系

按用户本轮重点修订叙事方向：角色应有让玩家愿意相处的魅力，日常相伴、交流、暧昧或亲近的发展由人物与经历推动；战斗保持危险、节奏、视觉张力和能力表现。两者共同构成主要游玩内容。情感互动本身可以推动剧情，不必每次借战斗、任务或检定证明价值。

成熟的角色设定需要能持续演绎的性格、行为逻辑、欲望/牵挂、经历、技能、审美习惯、语言特点和关系空间。沿用镜渡经用户实测的完整性与辨识度要求，迁移时剥离镜待流年的专属绑定。主角与她们的关系可以有不同起点，后续记录实际互动与变化；长期人设与本局相识状态、位置、正在做的事继续分层。

作者档案按全知视角合理补齐并延续事实；人物知情和正文揭示依据其经历与场景。玩家行动、回应与选择由玩家参与形成。计算脚本负责必要的资源与结果，正常的对话和亲近自然叙写，不被硬核机制挤成机械播报。

## 7. 顺序与token预算

继续沿用 docs/世界书顺序规划.md 与 src/worldbook-order.ts 的区间。当前1–1000为核心与叙事，1001–2000为通用机制，2001–3000为具体传承源条目，3001–4000为主要控制器，4001–5000为行动/人物/成长；7001–10000分配状态与输出；10001以后分配关闭源资料。具体插入位置与深度见源配置。

新增背景史、神器、玩法和开局先按类别规划，Codex集成时为新类别留出区间。EJS getwi输出实际位于控制器所在位置，源条目的数字不赋予其独立注入位置。共同背景简明常驻，长历史、神器全文与各玩法细则按当前话题、持有、地点及已知线索调用；完整正文仍存世界书，避免每轮把六件神器与所有玩法全量注入。
