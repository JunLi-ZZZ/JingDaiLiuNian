# 镜待流年立绘工坊

后端与角色卡升版独立。提供 Discord 登录投稿、作者查看自己的审核状态，以及管理员预览、审核发布、撤回、封禁和容量清理。浏览下载及本地使用不需要登录；玩家投稿使用独立账号，不使用管理员口令。

## 已有资源

- Worker：`jingdai-workshop-api`
- 地址：`https://jingdai-workshop-api.zhongyinglei377.workers.dev`
- D1 绑定：`DB`，数据库：`jingdai-workshop`
- R2 绑定：`PORTRAITS_BUCKET`，私有桶：`jingdai`

控制台已经绑定资源后，不需要在源码填写 Database ID、Cloudflare API Token 或 R2 密钥。不要公开 R2 桶，也不要把管理员口令写进角色卡。

## 从现有只读部署升级

1. 确认 D1 已有 `schema.sql` 的四张基础表。已有数据库无需重复建库或删表。
2. 打开 **Workers & Pages → jingdai-workshop-api → Settings/设置 → Variables and Secrets/变量和机密**，新增类型为 **Secret/机密** 的 `ADMIN_TOKEN`。用密码管理器生成至少 32 字符的随机口令，私下保存，不发到聊天里。界面若提示部署或保存，完成该操作。
3. 在 Worker **Edit code/编辑代码** 中打开已经存在的 **worker.js**，全选替换为本目录 `worker.mjs` 的全部内容，点击 **Deploy/部署**。文件名保留 `.js` 即可，不必新建 `.mjs`。
4. 访问 `/admin`，输入刚才的随机口令，点击“补全数据库结构”。它通过 Worker 的 D1 batch 执行固定的 `002-storage` 至 `009-lore-categories` 增量结构，每个触发器保持为完整的一条语句，不依赖网页控制台拆分 SQL。成功后自动进入管理页。已有表、投稿、会话和容量配置保留，可重复执行；不接受自定义 SQL。
5. 访问 `/health`、`/groups` 检查公开接口。

全新数据库才需要先执行 `schema.sql` 再执行迁移。不要删除数据库重来。

## 启用 Discord 登录投稿

1. 在 Discord Developer Portal 创建应用，在 **OAuth2 → Redirects** 添加并保存 `https://jingdai-workshop-api.zhongyinglei377.workers.dev/auth/discord/callback`。保持公共客户端关闭；不需要创建 Bot、加入服务器或获取消息权限。
2. 在 Worker 的 **Settings → Variables and Secrets** 添加文本变量 `DISCORD_CLIENT_ID`，值为 `1556568349285027932`；添加机密 `DISCORD_CLIENT_SECRET`，值从该 Discord 应用的 OAuth2 页面复制。不要写入源码、角色卡或聊天。
3. 将本目录最新 `worker.mjs` 的全部代码替换到 Worker 已有的 `worker.js`，点击 **Deploy/部署**。不要只新增一个未被入口引用的文件。
4. 访问 `/admin`，输入 `ADMIN_TOKEN` 的原口令，点击“补全数据库结构”。即使此前迁移仅完成一部分也可执行，不需要在 D1 控制台再次粘贴 `003-discord.sql`。若提示基础表缺失，才先执行 `schema.sql`。
5. 访问 `/submit`，点击“使用 Discord 登录”。授权只申请 `identify`，返回后应显示本人账号与投稿表单。会话有效期为 7 天，Discord access/refresh token 不保存到数据库、不交给浏览器。
6. 上传小型测试组，应进入“待审核”；未登录的公开目录看不到它。管理员在 `/admin` 审核发布后，公开目录才显示。先验证此流程，再发布角色卡新版。

若登录显示未配置，检查 Secret 是否保存并部署；若出现回调地址错误，检查 Discord Redirects 与上面的地址完全一致。更换 Secret 后需更新 Worker 机密并部署，不要重建数据库。

## 收稿、审核、公开

1. 作者可以在卡内立绘图库中整理、合并本地组并导出投稿组包，再打开“Discord 登录 / 我的投稿”；也可以在 `/submit` 直接批量选择本机图片。组包要求包含图片数据，不接受外链；服务器不会抓取第三方网址。
2. 作者在 `/submit` 登录后选择组包或批量图片，填写说明、确认拥有公开分享权限并提交。几百张 CG 宜直接批量选择图片，浏览器逐张上传并支持重新选择相同文件续传。署名由登录账号生成，上传后默认不可公开读取。小组包也可私下交给管理员在 `/admin` 收稿。
3. 点击“查看图片”，核对内容、角色、标签、版权授权和个人隐私，再决定发布或拒绝。
4. 发布后，玩家在卡内“立绘图库 → 云端工坊”预览，可将云端内容合并到当前本地组、按相同登记 ID 替换，或下载组包。不同作者的角色图片可整理进同一本地组；上传成新的公开组仍需作者拥有这些图片的分享权。
5. “撤回”隐藏云端组与图片，但保留存储，可重新审核发布。“清理图片”不可恢复地删除 R2 图片并释放容量，保留投稿及审核记录。

管理员口令仅保留在管理页本次内存中，刷新或退出后需要重新输入。泄漏后应在 Cloudflare 更换 Secret。

普通组包导出、云端合并和下载保留图片直链，不逐张抓取图片，适合多图组；本地导入也保留有效直链。需要换设备离线游玩时，点击“离线备份”，才会逐张下载并嵌入图片数据，文件可能很大。云端图片撤回或清理后，普通直链组包中的图片会失效；已经下载的离线备份无法远程收回。本地文件导入导出不依赖 Cloudflare。

本地导入、使用、导出与云端审核独立；投稿失败、待审或拒绝不改变作者的本地图库。换浏览器或设备时需导入本地备份，登录 Discord 不会自动同步本地数据。

## 作者维护

作者在 `/submit` 的“我的投稿”中可查看、追加图片、撤回和删除云端图片。点击已发布组的“更新组包”后，只选新增图片，或只含新增图片的组包；原组图片由服务器沿用，无需重新上传。新增图片的引用 ID 不能与原组重复。需要重组、删图、换图或改标签时，应先在本地整理目标组，并作为新投稿交审，旧组另行撤回或清理；原有一次性 JSON 更新接口暂保留兼容，但不是此页面的新增图片流程。

追加产生新的待审版本，沿用原作者权限及上传额度。审核期间已发布的旧版继续公开；新版审核通过时，数据库事务把旧图片及其容量记账转移到新版，再撤回旧版并发布新版。追加失败或拒绝不会改变旧版。每个原组同时只接受一个待审更新，之后继续维护最新版本；已沿用旧图的新版不能通过清理旧版误删图片。原组在待审期间被撤回、清理或改变状态时，更新需重新提交，不能借旧审核重新公开。

“撤回投稿”只隐藏云端内容并保留图片。“删除云端图片”经过确认后永久清理 R2 图片、释放容量，保留审核记录，支持清理失败后重试。两者均不删除本地图库及玩家已自行下载的备份。追加后旧图片的资源 ID 仍可在新版中读取；新版撤回或删除后直链失效，离线备份应保存图片数据。

升级此功能同样替换 Worker 入口并在管理页点击“补全数据库结构”，内置迁移包含 `006-append-revisions.sql`；无需手工删表。本轮增量更新只完成本地实现和模拟验证，尚未部署到 Cloudflare，也未升版发布角色卡。

## 容量与恢复

- 单图最多 **20 MiB**。新投稿流程逐张传图，单组支持最多 **2000 张**，没有 30 MiB 的整组图片上限；清单请求最多 **2 MiB**。几百张 CG 不应打包成一个巨型 JSON，在 `/submit` 直接批量选图。旧版管理员一次性 JSON 上传仍受 42 MiB 请求体及 24 张的兼容限制；base64 会增大体积，不适合大型图库。
- 每个玩家每分钟最多新建 1 次投稿、滚动 24 小时最多 5 次 / 2 GiB，最多 3 个待审组；玩家合计滚动 24 小时最多 4 GiB。失败尝试仍计入频率与每日额度，同一请求 ID 续传不会重复存图或预留容量。
- 管理员可暂停全站玩家投稿或封禁特定作者；封禁只限制新投稿，已有内容仍由管理员决定发布、撤回或清理。
- 默认总预留额度为 **8,000,000,000 字节**，给其他数据和运维留出余量。这是本应用限额，不是 Cloudflare 账单上限；请求次数等仍按平台规则计费。
- 接收 JPEG、PNG、WebP、GIF、AVIF，校验文件头与声明类型，不接收 SVG。文件头校验不等于内容审核，发布前仍需人工查看。
- 上传先在 D1 原子预留容量，再逐张写入 R2，并发投稿不能超过总额度。草稿图片只有作者和管理员能查看，全部上传完才可提交审核；中断后重新选择相同文件可续传，也可删除草稿释放容量。
- 上传失败会尝试清理。无法确认数据库是否已提交、或 R2 删除失败时，保守保留预留容量，避免漏计实际存储。
- 超过一小时且没有对应组的残留会出现在后台，可以“清理残留”。一小时内不能清理，以免删除仍在写入的对象。
- 图片清理失败的组标为“清理待完成”，期间不能发布；恢复后再次“清理图片”即可继续。清理成功前不会释放额度。
- 管理页按状态显示数量，默认只显示待审核；支持状态筛选、组名/作者/角色/标签搜索和稳定分页。公开列表也支持分页。

R2 保持标准存储。建议另设 Cloudflare 用量通知；应用限额不能替代平台账单监控。

## 接口

公开接口不需要口令，只返回已发布内容：

- `GET /health`：D1 与绑定基础检查，不代表 R2 写入和审核已验证。
- `GET /groups?limit=20&cursor=...&sort=latest|hot&q=关键词`：已发布组列表，最多 50 条；搜索组名、说明、作者、已发布图片的角色名和标签。热度为 `下载次数 * 4 + 使用次数 * 6`。
- `GET /groups/:id`：组详情与立绘目录。
- `GET /groups/:id/export`：兼容本地图库的完整组包，保留原始立绘 ID。
- `GET /assets/:id`：通过发布状态校验后读取 R2 图片。

管理页为 `/admin`，管理 API 在 `/admin/api`，要求 `Authorization: Bearer <ADMIN_TOKEN>`。支持 `summary`、`submissions`、组/图片预览、`moderate`（publish/reject/withdraw）和组图片清理。带 Origin 的请求只接受同源；Token 未设置或过短时拒绝管理操作。

`POST /admin/api/setup` 仅允许同源管理员请求，要求空请求体。只补齐内置的表、索引和触发器并回填缺失的容量预留；批处理中任一语句失败则整批回滚。不会降低限额、重置容量或清空数据。内嵌迁移与 SQL 文件的一致性由测试检查。

目录请求只执行 D1 查询，不写热度；封面使用懒加载，浏览器实际需要时才读取对应的 R2 对象。预览和普通下载先读取组包 JSON，图片仅在预览展开或离线备份时按需读取。合并/替换和下载/离线备份分别只在用户明确点击后增加一次使用/下载统计。搜索输入在提交后才请求 Worker，不会因每次按键产生请求。

## 玩家接口与后续边界

投稿页为 `/submit`，登录入口为 `/auth/discord`，回调为 `/auth/discord/callback`。玩家 API 在 `/account/api`，使用 HttpOnly Cookie 会话；写操作同时校验同源与 CSRF，投稿还校验幂等请求 ID。待审内容仅作者本人和管理员可预览。

当前审核是人工审核，文件头校验不等于内容审核或完整图片解码。角色世界书分享使用独立的角色包格式，可关联已发布立绘组，见下文。

## 角色设定与世界书工坊（本地实现，尚未部署）

2026-10-20：此功能已接入当前源码和隔离预览；未替换线上 Worker，未升版、推送或更改已发布卡的 CDN 引用。已有 v230 母镜修改另存本地检查点，仍保留在工作区。

### 投稿、审核与使用

1. 卡内从状态栏“角色工坊”进入，浏览已发布角色，支持最新、最热、搜索和分页。点击角色时在对应条目下展开完整设定；最热按角色包下载次数排序，不宣称是去重用户数。
2. 作者可以在“制作 / 导入设定包”填写资料名称、角色／位面／其他分类、简介和多条设定，每条填写名称、关键词和正文，保存本地草稿或导出 `jdnl-character-package` v1 JSON。角色包和立绘组包是不同格式。此版本不直接导入其他作品的整张 PNG 卡，也不复制脚本、正则或 EJS。
3. 在 `/characters-submit` 使用现有 Discord 会话投稿。首次登录沿用 `/auth/discord`；授权返回原 `/submit` 后，可从页头进入“角色设定投稿 / 我的角色”。投稿默认待审，署名取登录账号。作者可按待审、已发布、已拒绝、已撤回查看自己的投稿，并撤回或基于已处理稿提交更新。
4. 管理员从 `/admin` 页头进入 `/characters-admin`，使用原 `ADMIN_TOKEN`。默认显示待审核队列，提供状态数量、搜索、全文预览、审核备注、发布、拒绝、撤回和暂停作者投稿。文字按纯文本显示，不执行条目中的 HTML 或模板。
5. 玩家预览后点击“加入世界书”。默认写当前聊天绑定的世界书，没有则新建；也可从选择器选当前卡已绑定的主世界书、附加世界书或聊天世界书。默认创建关键词触发条目并禁止相互递归；逐条配置可覆盖默认值，保留原有其他条目。
6. 世界书条目在 `extra.jdnl_character_workshop_v1` 记录包 ID、角色版本族 ID、条目 ID、作者和设定签名。重复安装不重复创建；同一作者的角色更新按版本族和条目 ID 替换，保持 UID、启用状态，自动顺序在同分类更新时保持，其他设置按所选配置写入。同名的其他作者角色彼此独立。本地改过的内容、条目名、关键词、顺序、位置、概率、递归或定时配置会阻止覆盖；只有玩家主动勾选覆盖选项后才替换。
7. 作者更新产生新待审稿，旧稿继续公开；新版通过审核后在数据库事务内撤回旧稿。原稿在审核期间被撤回或改变状态，旧审核不能将其重新发布。云端撤回不删除玩家已经导入的本地世界书。

### 分类与自动导入配置

资料包与条目分别支持角色、位面、其他；条目默认跟随资料包分类，也可单独覆盖。目录、作者列表和管理员列表均可按分类筛选。协议仍为 `jdnl-character-package` v1，旧包缺少分类和配置时补齐默认值。

自动顺序区间：位面 10001–10999、角色 11001–11999、其他 12001–12999。导入避开同插入位置已有的顺序及同包手动指定的顺序，每类创建一个禁用的分类分隔条目；分隔条目不注入提示词。每次加入按当前世界书重新计算，“预览加入结果”只读取和计算，不创建或写入世界书。

每条“世界书配置”支持：自动或手动顺序、蓝灯／绿灯、插入位置、指定深度及消息身份、扫描深度、激活概率、次要关键词与逻辑、禁止被递归激活、禁止继续递归、延迟递归、黏性、冷却和延迟激活。关键词留空自动使用资料名称；有“一键恢复自动配置”。这些设置会随导出、投稿、审核、云端下载和本地导入保留。玩家可以在云端资料预览中为本地安装调整设置，不更改作者的云端原稿。

新增 `009-lore-categories.sql` 只给角色表增加分类字段与索引；管理页结构补全会先检查列是否存在，可重复执行并保留旧投稿。分类与顺序计算在客户端完成，不增加定时查询。

### 配套立绘

角色包中的 `character.portrait_group_id` 可指向现有已发布的立绘组。云端立绘目录、作者投稿列表和管理员列表显示可复制的组 ID；配套图片先使用原立绘投稿流程审核发布，然后把组 ID 填入角色包。

角色投稿与发布时都会检查关联组是否已发布。角色预览会说明配套组是否仍可用；立绘撤回后，不会通过角色包绕过原图权限。角色文本可单独继续使用。作者应让立绘登记角色名与设定中的角色名一致，以便现有分类目录引用。

玩家可主动勾选“同时导入配套立绘并设为当前组”。图片沿用已发布资源直链，不复制到云端、不逐张转存。导入形成按角色版本族区分的本地组，图片登记 ID 增加角色命名空间；后续更新仅追加新登记项，保留本地已有图片和编辑。文字与图库分两步保存，若图库保存失败会明确告知“角色设定已保存，立绘导入失败”，可重试。

### 访问与应用限额

- 角色文本存于现有 D1 的独立角色表，图片继续使用现有 R2 立绘存储；不需要新桶、新数据库或新密钥。
- 只在打开工坊、搜索、翻页、预览、投稿或下载时访问云端；导入后的设定由本地世界书提供。卡内目录和详情在组件模块内缓存两分钟、最多 40 项，手动刷新和正式安装会重新核对云端状态；不定时轮询。
- 普通预览、搜索、安装均不写热度统计；玩家主动“下载角色包”才增加一次下载计数。这是原始请求计数，不是去重人数，也不保证防刷。
- 单包最多 256 KiB、32 条设定、单条正文最多 30000 字符、单条最多 20 个关键词。应用默认保留的角色文本总额 64 MiB，可由数据库 `character_workshop_quota.limit_bytes` 调整；与原立绘容量分开记账。这些是应用保护限额，不是 Cloudflare 账单上限。
- 作者每分钟最多一稿、24 小时最多五稿、最多三稿同时待审；全站 24 小时最多 200 稿。数据库触发器原子检查限额。账号封禁和 `PLAYER_UPLOADS_ENABLED` 开关同时作用于角色和立绘投稿。请求 ID 保证同一稿重试不重复保存。
- 不接收 EJS、脚本标签或可执行宏；`{{user}}`、`{{char}}` 作为普通角色称呼宏保留。角色卡原有生成、变量结算和世界书规则不由云端稿件修改。

## 卡内分类引用

立绘目录由当前本地组的真实登记项生成。**角色名与完整标签完全相同**的项归为同类，不归并近义词或服装、姿态的不同标签。模型收到按角色列出的完整分类目录，输出 `[[portrait-set:分类id]]`；每类 ID 由 `JSON.stringify([角色名, 完整标签])` 的 SHA-256 前 16 个十六进制字符加 `s_` 前缀构成。逐图 URL 与逐图登记 ID 不进入这一目录，新增角色不会因未出现在旧剧情中而漏出目录。

客户端从实际登记图中随机选择，选定的登记 ID 存到当前回复的 `extra.jdnl_portraits_v1`，并同步当前 `swipe_info`。同一分类在正文中出现多次时按出现顺序分别记账；重绘、刷新、编辑前后正文、移动楼层及切回旧 swipe 保持选择。新 swipe 可得到独立选择，随机结果允许恰好相同。追加候选不改变已选图；删除已选项才会重新选择。关闭立绘时不创建选择记录。

加载失败只在原分类内尝试其他实际登记图，同类全失败后停止并显示“重试加载”。重试会清除该引用的本次失败记录；修改图片 URL 后也可重新尝试。失败记录仅在当前脚本内存中，刷新或切换聊天后重新检查资源；已选登记 ID 随酒馆消息保存。批量保存避免每次重绘都写聊天，流式生成期间延后，生成结束后补存。

旧 `[[portrait:登记ID]]` 与 `<portrait id="登记ID">` 仍指定原图，失败时仅重试该图。修改角色名或完整标签会产生新分类 ID，旧正文里的分类标记不会自动改写；当前组没有该分类时保留正文且不显示图片。图库组切换按组区分选择，既有登记 ID 与组包格式无需迁移。

本次立绘分类引用使用现有 `id/name/tag/url`，**无需新增 Cloudflare 表、接口或密钥**。旧版增量更新是否生效取决于此前 Worker 入口部署与管理页结构补全；那一步包含 `006-append-revisions.sql`，与卡内分类渲染独立。世界书工坊另需 `008-character-workshop.sql` 和 `009-lore-categories.sql`。v231 卡片统一使用 `dist/镜待流年_v231`，包含世界书工坊、自动分类与完整导入配置，以及母镜正背面展示修正。
