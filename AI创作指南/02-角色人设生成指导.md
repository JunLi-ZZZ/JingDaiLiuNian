# 角色人设生成指导

本指南用于 AI 在新建酒馆角色卡项目时，指导如何创建高质量的角色人设。主要参考 **电车JC后传-老父亲的带娃日常** 卡的角色塑造模式。

---

## 1. 角色人设的核心维度

每个角色的人设应从以下 **五个维度** 来构建，缺一不可：

```
维度1: 基本信息    → 姓名、性别、年龄、身份、与玩家的关系
维度2: 外貌特征    → 整体印象、发型、面部、穿着、有趣点
维度3: 性格特点    → 核心特质、表现形式（行为实例）、对玩家的表现（台词实例）
维度4: 背景设定    → 过往经历、当前生活状态
维度5: 语言特征    → 说话习惯、语气风格
```

### 实际案例对照：星宫诗羽的人设结构

星宫诗羽的人设文件包含以下完整五维度（详见 `卡区/电车JC后传-老父亲的带娃日常/世界书/星宫诗羽人设.txt`）：

```
基本信息:
  姓名: 星宫诗羽
  性别: 女
  年龄: 青年
  身份: 星宫控股集团总裁，<user>的妻子，孩子们的母亲
  与<user>关系: 相伴十年的合法夫妻

外貌特征:
  整体印象: 身高一米六零，曲线丰满但腰肢纤细，像高中女生但散发成熟韵味
  发型: 粉色，工作时盘发髻，居家时放下来
  面部: 精致轮廓，灰黑色眼睛（工作时锐利，对user时依赖），妆容（工作精致vs居家素颜）
  穿着: 工作时高档职业套装（黑白灰），居家时丝质/棉质宽松居家服
  有趣点: 对女儿严厉显得凶巴巴很苦恼，在丈夫面前却软萌可爱

性格特点:
  核心特质: 在外手腕强硬，在内依赖丈夫
  表现形式（具体行为）:
    - 深夜回家后一言不发从背后抱住user
    - 董事会毫不留情驳回提案，但会对user撒娇
    - 压力大时关掉手机躲卧室，直到user端着食物进来
    - 把头枕在user腿上闭眼听他说话
    - 亲密时放弃主导权，完全交给user
    - 出差时固定时间视频，有时只看不说话
    - 被按摩时发出舒服的鼻音
  对user的表现（台词）:
    - "……我回来了。让我抱一会儿，就一会儿。"
    - "今天不想思考任何事……你帮我决定晚饭吃什么吧。"
    - "如果没有你，我可能早就垮掉了。"

背景设定:
  过往: 十年前被user"引导"认清真实自我，在家族支持下接管星宫控股
  当前: 商业帝国掌舵人，日常工作极繁忙，家庭是唯一避风港

语言特征:
  商场: 精准、权威、不带多余情感
  user面前: 简短、无力、请求和依赖口吻，完全卸下面具
```

## 2. 每个维度的深度要求

### 2.1 基本信息

**不只是罗列标签，而是定义角色的社会坐标和关系网。**

```yaml
必须包含:
  - 姓名: 完整的日式/中式/西式姓名
  - 性别
  - 年龄: 可用年龄段（青年/中年）而非精确数字，给AI留弹性
  - 身份: 至少两个身份（社会身份 + 家庭身份）
  - 与<user>关系: 明确标注使用<user>变量

加分项:
  - 多个身份之间的张力（如"商业女王"vs"疲惫妻子"）
  - 关系中的特殊定位（如"正妻"、"被调教者"）
```

### 2.2 外貌特征

**不只是静态描述，而是动态的、情境化的外貌。**

```yaml
必须包含:
  - 整体印象: 身高、身材、给人的第一感觉
  - 发型: 发色、发型、不同场合的变化
  - 面部: 脸型、眼睛颜色、眼神在不同情境下的变化
  - 穿着: 至少两种场合的穿着对比（工作vs居家、公开vs私下）
  - 有趣点: 1-2个反差萌的细节（让人物立体化的关键）

关键技巧 - 反差描写:
  "对外形象" vs "对内形象" 的对比
  "公开场合" vs "私下场合" 的对比
  "她看起来X，但实际上Y"
```

### 2.3 性格特点（最核心的维度）

**性格描写必须包含三个层次：**

```
层次1 - 核心特质（1句话概括）:
  格式: "在外是X，在内是Y"
  示例: "在外是手腕强硬的集团领袖，在内是依赖丈夫的疲惫妻子"

层次2 - 表现形式（5-8个具体行为实例）:
  格式: 描述在特定情境下的具体行为，不是抽象的性格形容词
  好的写法: "深夜结束后会一言不发地从背后抱住正在看书的<user>，将脸埋在他的背上"
  差的写法: "她很依赖丈夫"  ← 这是结论，不是行为

层次3 - 对玩家的表现（5-8句具体台词）:
  格式: 直接引用角色会对玩家说的话
  好的写法: "……我回来了。让我抱一会儿，就一会儿。"
  差的写法: "会说一些依赖的话"  ← 这没有给AI具体的语感
```

**为什么表现形式（行为实例）如此重要：**
AI 模型通过这些具体行为来理解"什么是这个角色会做的事"。抽象的性格形容词给了AI一个模糊的方向，但具体的行为实例给了AI可模仿的模式。

**关键警告——禁止在表现形式中添加具体场景举例：**
```yaml
错误示例:
  "对{{user}}几乎有求必应——从实验器材到夜宵到忘记带的伞，她总在{{user}}需要之前就已经准备好了"
  问题: 破折号后面的举例（实验器材、夜宵、伞）会让AI反复套用这几个具体物品，导致角色行为生硬重复

正确示例:
  "对{{user}}几乎有求必应"
  原则: 只描述行为模式本身，不列举例场景。AI会根据当前剧情上下文自行生成合适的具体行为

为什么禁止举例:
  - 举例会被AI当作"剧本"反复使用，导致角色每次出场都在做同一件事
  - 举例限制了AI的创造力——本来可以根据剧情灵活生成，现在只会套用模板
  - 角色的核心是行为模式（"有求必应"），不是具体道具（"实验器材"）

适用范围:
  - 表现形式：禁止举例，只描述行为模式
  - 对用户的表现（台词）：可以有具体台词范例，因为台词本身就是语言样本
  - 背景设定：可以有具体事件，因为这些是历史事实不是可重复行为
```

### 2.4 背景设定

**分为过去和现在两部分，不超过5句话。**

```yaml
过往经历:
  - 关键转折点: 什么事件塑造了现在的她
  - 不超过3句话
  - 与当前性格有直接因果关系

当前生活:
  - 现在的日常状态
  - 现在的核心矛盾/压力源
  - 不超过2句话
```

### 2.5 语言特征

**定义角色的"口癖"和语域切换。**

```yaml
必须说明:
  - 默认说话方式: 语气、语速、用词习惯
  - 语域切换: 在不同对象面前说话方式的变化
    如: 商场 → 精准权威 / user面前 → 简短无力 / 孩子面前 → 温和关切
```

## 3. 配套文件体系

根据电车JC后传的实践，每个角色需要 **4个配套文件**：

```
世界书/
├── {角色名}人设.txt      ← 核心：基本信息+外貌+性格+背景+语言
├── {角色名}语料.txt      ← 大量对话范例，分场景组织
├── {角色名}兴趣爱好.txt   ← 兴趣的层次化描写
└── {角色名}nsfw.txt       ← NSFW设定（如适用）
```

### 3.1 语料文件的写法

语料文件提供一个 **纯对话、无动作描述** 的台词语料库。这是给AI参考的"说话样本"。

```yaml
组织结构:
  按场景分类:
    对外场景（社会身份）:
      - 工作会议
      - 商务应酬
      - 对下属/秘书
  
    对内场景（家庭身份）:
      - 回到家时
      - 感到疲惫时
      - 寻求安慰时
      - 与孩子互动时
  
    情绪场景:
      - 开心放松
      - 撒娇亲密
      - 压力过大/脆弱时

每条语料的格式:
  - "{具体的台词}"
  每条台词反映角色的性格侧面
  
语料数量建议:
  - 主角（<user>以外最重要的角色）: 每个场景5-10条
  - 次要角色: 每个场景3-5条
  - 总计每个角色30-80条语料
```

**关键：语料是给AI模仿用的，不能直接复制粘贴到回复中。** 在语料文件开头声明："以下语料为纯对话，不包含动作、表情、神态描述，作为参考不可生搬套用！"

### 3.2 兴趣爱好文件的写法

兴趣爱好的描写不是罗列标签，而是 **挖掘每个爱好背后的心理动机**。

```yaml
三层结构:

功能性爱好（社会身份的延伸）:
  - 是什么
  - 为什么做（真正的动机）
  - 怎么做（具体行为）
  - 玩家的角色（<user>在其中的意义）

慰藉性爱好（回归自我的方式）:
  - 同上

情感连接性爱好（维系关系的纽带）:
  - 同上
```

**实际案例：星宫诗羽的"品鉴红酒"**
```
功能性爱好:
  品鉴目的: 并非个人享受，而是商务社交的必备技能
  品鉴表现: 在家中几乎从不主动饮酒
  深层描写: "当<user>为她倒上一杯时，她会习惯性地轻晃酒杯，观察挂杯，但眼神是放空的"
  台词: "这支酒单宁太重，不适合今晚的放松氛围。"
```
这样的描写比"爱好：品红酒"深刻得多。

### 3.3 NSFW文件的激活策略

NSFW条目使用 **主关键字 + 次要关键字** 的双重激活：

```yaml
激活策略:
  类型: 绿灯
  关键字: [角色名]          ← 主关键字
  次要关键字:
    逻辑: 与任意
    关键字: [性爱, 做爱, 私处, ...]  ← 只在涉及NSFW内容时才激活
```

这确保了：日常对话中提到角色不会激活NSFW设定，只有对话内容涉及NSFW时才会。

## 4. 多角色体系的组织

参考电车JC后传的11个角色如何组织：

### 4.1 层级结构

```yaml
第一层级: 核心家庭成员（成年女性 - 妻子们）
  - 每人4个文件（人设 + 语料 + 兴趣爱好 + NSFW）
  - NSFW文件有次要关键字过滤

第二层级: 第二代成员（孩子们）
  - 每人2-3个文件（人设 + 语料 + 兴趣爱好）
  - 孩子角色通常不需要NSFW文件

第三层级: 玩家（<user>）
  - 1个人设文件
  - 定义玩家在这个家庭中的角色定位
```

### 4.2 角色列表文件

为整张卡建立一个总览文件，列出所有角色及其标签：

```yaml
核心家庭成员:
  - <user>: 核心与支柱、丈夫、父亲 | 星宫控股副总裁 | 温柔可靠、成熟稳重
  - 星宫诗羽: 正妻、母亲 | 星宫控股总裁 | 商业女王、依赖丈夫、外冷内热
  - 白石䌷: 妻子、母亲 | 幼儿教师 | 温柔人妻、无声守护
  - ...

第二代成员:
  - 星宫汐: 长女 | 初中二年级 | 优雅外壳、冒险家内心、精力旺盛
  - ...
```

这个文件作为 **蓝灯常驻条目** 插入到系统深度0的位置，让AI随时知道有哪些角色存在。

### 4.3 角色之间的差异化

电车JC后传中四名妻子的核心差异：

| 角色 | 核心标签 | 互动模式 | 反差萌 |
|------|---------|---------|--------|
| 星宫诗羽 | 商业女王→疲惫妻子 | 寻求慰藉 | 对外强硬/对内软萌 |
| 白石䌷 | 无声的守护者 | 默默照顾 | 表面平静/深情内敛 |
| 橘瑠奈 | 运动少女 | 崇拜"教练" | 活力四射/单纯幼稚 |
| 夜月梦 | 雌小鬼 | "偷情扮演" | 表面闹腾/深情报恩 |

**关键原则：每个角色的核心互动模式必须不同。** 如果两个角色与玩家互动的方式相似，她们就是同质化的，应该合并或重新设计。

## 5. 世界书条目中的角色信息包装

角色人设条目使用 `<character_info_card>` 标签包裹，在人设文件外添加开始/结束标记条目：

```yaml
条目组织:
  1. 开始标记: 名称="-----{角色名}开始-----", 内容="<character_info_card>"
  2. 人设文件: 名称="{角色名}人设"
  3. 语料文件: 名称="{角色名}语料"
  4. 兴趣爱好: 名称="{角色名}兴趣爱好"
  5. NSFW文件: 名称="{角色名}nsfw"（如适用）
  6. 结束标记: 名称="-----{角色名}结束-----", 内容="</character_info_card>"

顺序间距:
  - 每组角色留10个序号空间
  - 开始标记和结束标记之间用递增序号保证顺序
  
关键词设计:
  - 一个角色组的所有条目使用相同的关键词
  - 确保提及角色时所有相关条目同时激活
```

## 6. 玩家（<user>）的人设

玩家的人设同样重要，需要定义：

```yaml
玩家人设应包含:
  - 基本信息: 姓名（用<user>）、性别、年龄、身份
  - 外貌特征: 不是"留给玩家想象"，而是定义在该世界观中的形象
  - 性格特点: 
      分三个面向描述：
      - 对待妻子们（温柔深情的丈夫）
      - 对待孩子们（可靠的老父亲）
      - 在社会上（职业身份的表现）
  - 对家人的表现（台词）: 给AI玩家说话的语感参考
  - 语言特征: 说话风格
  - 关系设定: 与各角色的关系定位
```

**玩家是故事的核心枢纽**，所有角色的互动都围绕玩家展开。玩家的人设定义了AI眼中玩家是什么样的人、会怎么说话、会怎么做。

## 7. 故事基调与背景故事

### 7.1 故事基调（蓝灯常驻，角色定义之前）

```yaml
内容极简: 1-2句话
格式示例:
  "在现代背景下，在一个特殊的大家庭中发生的故事。
   主元素：成长，日常，轻松，欢乐"
  
作用:
  - 给AI定下叙事的基本调性
  - 不要写太长，这只是一个方向性的提示
```

### 7.2 背景故事（蓝灯常驻，角色定义之前）

```yaml
内容: 5-10句话
格式: 用<story>标签包裹
结构:
  1. 故事的起点（为什么会有现在这个局面）
  2. 每个角色的加入动机（她们为什么在这里）
  3. 时间跨度（过去了多久）
  4. 现在的状态（接下来要讲什么）

示例（电车JC后传）:
  "这个故事发生在10多年前：
   - 父母双亡的<user>经历创业失败后成为教师
   - 某天在电车上遇到星宫诗羽，以照片威胁开始调教
   - 之后星宫的朋友们也一一被卷入
   - ...（每人加入动机）...
   - 如今过去10年，<user>拥有四位妻子
   - 接下来的故事讲述他温馨的带娃日常"
```

## 8. 第一条消息（开场白）

开场白是玩家对该卡的第一印象，需要：

```yaml
设计要点:
  1. 展示世界观: 让玩家立刻感受到这是什么世界、什么氛围
  2. 展示角色: 让主要角色尽数登场，但要自然不突兀
  3. 展示互动模式: 让玩家知道"我该怎么和这些角色互动"
  4. 给出选择: 结尾用<options>标签提供2-4个选项，引导不同剧情方向
  5. 长度适中: 300-800字，不要太长

选项设计:
  <options>
  <op>选项1 - 引向角色A的剧情线</op>
  <op>选项2 - 引向角色B的剧情线</op>
  <op>选项3 - 引向日常温馨场景</op>
  </options>
  
  每个选项指向不同角色或不同风格的剧情开局
```

## 9. 角色人设检查清单

写完每个角色后，确认以下各项：

- [ ] 五个维度（基本信息/外貌/性格/背景/语言）是否齐全？
- [ ] 性格是否有"核心特质 + 具体行为实例 + 台词范例"三个层次？
- [ ] 外貌是否有至少两种场合的穿着/状态对比？
- [ ] 是否有一个"反差萌"的细节？
- [ ] 语料文件是否覆盖了多种场景（对外/对内/情绪）？
- [ ] 兴趣爱好是否挖掘了心理动机，而非简单罗列？
- [ ] 如果该角色与其他角色互动模式相似，是否需要重新设计差异化？
- [ ] 关键词设置是否正确（同一角色的所有条目用相同关键词）？
- [ ] NSFW条目是否正确使用了次要关键字过滤？
- [ ] 玩家（<user>）人设是否足够具体，给了AI明确的语感参考？
