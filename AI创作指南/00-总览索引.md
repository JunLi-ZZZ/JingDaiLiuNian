## 新建一张卡的决策流程

```
开始
  │
  ├─→ 卡的类型是什么？
  │     ├─ 轻量日常卡（如电车JC后传）
  │     │     → 阅读: 01 世界观 + 02 角色人设
  │     │     → 不需要: MVU / EJS
  │     │     → 可选: 05 前端美化（正则替换部分）
  │     │
  │     ├─ 中型RPG卡（有数值系统，1-2个时代）
  │     │     → 阅读: 01 + 02 + 03 (MVU)
  │     │     → 可选: 04 (EJS，如果NPC多)
  │     │     → 可选: 05 (前端美化，如果有状态栏界面)
  │     │
  │     └─ 大型世界卡（3+时代/区域，50+NPC）
  │           → 阅读: 01 + 02 + 03 + 04 (全部)
  │           → 推荐: 05 (前端美化)
  │
  ├─→ 是否需要追踪数值状态（HP/等级/好感度/物品栏）？
  │     → 是: 必须使用 MVU (03)
  │     → 否: 不需要 MVU
  │
  ├─→ NPC/地点数量是否超过30个且随时代变化？
  │     → 是: 强烈建议使用 EJS (04) 按需加载
  │     → 否: 传统世界书关键词激活足够
  │
  └─→ 是否需要前端状态栏/面板？
        → 是: 阅读 05 前端美化 + 03 MVU的store章节
        → 否: 可选使用正则美化 (05 第3节)
```

## 文件输出规范

新建角色卡时，根据卡的类型，需要产出的文件结构：

### 轻量日常卡
```
{卡名}/
├── index.yaml              ← 主定义（角色卡配置）
├── 头像.png
├── 第一条消息/
│   └── 1.txt
├── 世界书/
│   ├── 故事基调.txt
│   ├── 背景故事.yaml
│   ├── {角色名}人设.txt
│   ├── {角色名}语料.txt
│   ├── {角色名}兴趣爱好.txt
│   ├── {角色名}nsfw.txt     ← 如适用
│   ├── user人设.txt
│   ├── 角色列表.txt
│   └── [场景/地点文件...]
└── 正则/
    ├── 开场白.txt
    └── 美化选项.txt
```

### MVU 角色卡（在轻量日常卡基础上增加）
```
{卡名}/
├── ... (以上所有文件)
├── schema.ts                ← Zod 变量结构
├── 脚本/
│   ├── MVU/
│   │   └── index.ts
│   ├── 变量结构/
│   │   └── index.ts
│   └── [其他脚本]/
├── 界面/
│   ├── 状态栏/
│   │   ├── index.html
│   │   ├── index.ts
│   │   ├── store.ts
│   │   ├── global.css
│   │   └── components/
│   └── [其他界面]/
└── 世界书/
    └── 变量/
        ├── [initvar]变量初始化勿开.yaml
        ├── 变量列表.txt
        ├── [mvu_update]变量更新规则.yaml
        └── [mvu_update]变量输出格式.yaml
```

### 大型 EJS 卡（在 MVU 基础上增加）
```
{卡名}/
├── ... (以上所有文件)
└── 世界书/
    ├── EJS控制器.txt          ← 动态加载核心
    ├── {时代}：{NPC名}.txt    ← 按时代命名
    ├── {时代}：{地点名}.txt
    └── ... (大量按时代组织的条目)
```

## AI 使用本指南的方式

当收到"帮我新建一张XX类型的角色卡"的请求时：

1. **首先阅读本索引文件**，根据卡的类型确定需要参考哪些指南
2. **阅读 01 世界观**，确定世界书结构
3. **阅读 02 角色人设**，设计角色体系
4. **如需数值系统**，阅读 03 MVU
5. **如卡规模较大**，阅读 04 EJS
6. **如需前端界面**，阅读 05 前端美化
7. **参考实际案例**（卡区/中的对应卡片）获取灵感
