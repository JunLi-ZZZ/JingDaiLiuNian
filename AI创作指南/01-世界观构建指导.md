# 世界观构建指导

本指南用于 AI 在新建酒馆角色卡项目时，指导如何编写世界观/世界书条目。

---

## 1. 世界观的层级结构

一个完整的世界观应从宏观到微观逐层展开，参照以下层级结构组织世界书条目：

```
层级 1: 核心法则     → 世界运行的基本规则（如魔法体系、科技水平、种族设定）
层级 2: 世界格局     → 势力分布、地理版图、历史脉络
层级 3: 时代/时期     → 当前所处时代的具体状况
层级 4: 区域场景     → 玩家当前所在的具体地点
层级 5: 即时事件     → 正在发生的事件、任务、遭遇
```

### 实际案例：斗罗大陆3.0 的世界书结构

```
常驻加载:
  斗罗大陆核心规则          (层级1 - 核心法则：武魂、魂力、魂环体系)
  
按时代切换:
  斗一：世界格局 / 斗二：世界格局 / 斗三：世界格局   (层级2)
  斗一：剧情年表总纲（前期）/（中期）/（后期）        (层级3)
  斗一：序章 / 第一章 / ...                          (层级4)
  
按关键词触发:
  武魂评估规则、武魂融合技规则、魂兽基础设定、成神规则  (层级1补充)
  战斗描写指南、魂兽生成规则、经济系统              (层级5)
  
按场景类型互斥:
  战斗 / 猎魂 / 购物 / 亲密 / 日常                   (层级5)
```

## 2. 世界书条目的核心要素

每个世界书条目应当包含以下要素：

### 2.1 核心规则条目（层级1）

定义世界运行的底层逻辑。以斗罗大陆为例：

```yaml
条目内容应包含:
  - 力量体系: 等级划分、获取方式、进阶条件
  - 核心机制: 战斗规则、经济规则、成长规则
  - 限制条件: 哪些能做、哪些不能做
  - 判定方式: 如何裁决不确定结果（骰子、属性检定等）
```

**关键原则：规则要具体可执行，不能只写抽象概念。** 例如不要只写"这个世界有魔法"，而要写"魔法分为火水风光暗五系，每系有10级，升级需要冥想值和熟练度，施法消耗魔力值，魔力值 = 精神力 × 10"。

### 2.2 世界格局条目（层级2）

定义势力版图与地理分布：

```yaml
条目内容应包含:
  - 主要势力: 名称、立场、实力范围、关键人物
  - 地理版图: 主要区域、特色地貌、交通方式
  - 历史背景: 关键历史事件、当前政治局势
  - 冲突关系: 势力间的敌对/联盟关系
```

### 2.3 时代/时期条目（层级3）

当前时间节点的具体状态：

```yaml
条目内容应包含:
  - 时代特征: 当前时期的社会状态、科技/魔法水平
  - 主线剧情: 当前时期正在发生的大事件
  - 可用资源: 该时期特有的系统/机制
  - 关键NPC: 该时期在世的/可遇到的重要人物
```

### 2.4 区域/场景条目（层级4）

玩家当前所在位置的具体描述：

```yaml
条目内容应包含:
  - 场景外观: 环境描述、建筑风格、氛围
  - NPC列表: 此处常驻或可能遇到的NPC
  - 可用设施: 商店、训练场、任务发布处等
  - 可触发事件: 该场景可能发生的特殊事件
```

### 2.5 即时事件条目（层级5）

动态发生的事件/任务/遭遇：

```yaml
条目内容应包含:
  - 触发条件: 什么情况下激活该条目
  - 事件描述: 发生了什么
  - 可选行动: 玩家可以做什么
  - 结果/奖励: 不同选择的结果
  - 变量影响: 对MVU变量的影响
```

## 3. 世界书条目的编写规范

### 3.1 条目命名规范

参考斗罗大陆3.0的命名方式：

```
常驻规则:   "{世界观名}核心规则"、"NPC互动规则"、"剧情演化规则"
时代条目:   "{时代名}：世界格局"、"{时代名}：剧情年表总纲（{时期}）"
章节条目:   "{时代名}：{章节名}"
地点条目:   "{时代名}：{地点名}"
NPC条目:    "{时代名}：{NPC名}"
系统条目:   "{时代名}：{子系统名}设定"（如"斗三：锻造师设定"）
特殊规则:   "武魂评估规则"、"战斗描写指南"、"NSFW规则"
```

### 3.2 条目撰写风格

**原则：纯事实陈述，零修饰，零抒情。** 每条信息必须有实际用途，AI 不需要被"氛围"说服。

```yaml
必须遵守:
  - 只写客观事实，不添加文学性描写、情感渲染、氛围铺垫
  - 禁止使用比喻、拟人、排比等修辞手法
  - 禁止加入作者的主观评价或情感色彩
  - 每条信息都应能回答"这对AI扮演有什么用"

反面示例:
  错误: "图书馆四楼有一片几乎没人去的古籍区。偶尔有特殊读者——比如从仙道位面来查资料的女剑修，阳光透过高窗洒在泛黄的书页上，静谧如画"
  正确: "图书馆共四层，四楼为古籍区，人流量极少"

  错误: "虞姝昀的独立办公室在顶层走廊尽头，采光极好，但门总是半掩着，让人不敢轻易打扰"
  正确: "虞姝昀的独立办公室在顶层走廊尽头"

  错误: "这座城市慢半拍，温柔，像是被什么力量轻轻护着。来这里的人会莫名其妙地想多留几天"
  正确: "星见市为二线沿海都市。表面为普通现代城市，实为位面枢纽的核心锚点"

字数原则:
  - 能用列表不用段落，能用短句不用长句
  - 每一句话都应包含AI可操作的信息
  - 删掉所有"让读者感受氛围"的内容——AI不是读者，是执行者
```

### 3.3 条目内容组织

**原则：条目内容应当自包含，每个条目独立可读。** 即使多个条目间有重叠信息，也应各自完整描述。AI 可能在只激活部分条目的情况下生成回复。

### 3.4 条目的激活策略设计

```yaml
蓝灯（始终激活）:
  - 核心规则、世界观基础设定
  - 故事基调、第一人称设定
  - 适用于: 无论什么场景都需要的基础信息

绿灯（关键词激活）:
  - 角色设定（关键词：角色名）
  - 地点设定（关键词：地点名）
  - 特定系统（关键词：系统术语）
  - 适用于: 只在相关时才需要加载的内容
  - 多条目的关键词要有一致性，确保同一角色的所有条目能被同时激活

次要关键字（组合激活）:
  - NSFW条目：主关键字=角色名 + 次关键字=NSFW相关词汇
  - 适用于: 需要特定上下文才触发的内容

顺序编号管理:
  - 角色条目组: 开始标记(顺序41) → 人设(42) → 语料(43) → 兴趣爱好(44) → NSFW(45) → 结束标记(50)
  - 间距留白: 每个角色组之间留10个序号空间，便于后期插入新条目
```

### 3.5 互斥场景设计

对于同一时间只能发生一种的场景类型，使用互斥逻辑（参考斗罗大陆EJS控制器区块10）：

```
场景类型枚举: 战斗 | 猎魂 | 购物 | 亲密 | 日常
  - 每个场景类型加载不同的世界书条目
  - 通过检查场景类型变量 + 聊天关键词双重判断
  - 只加载第一个匹配的场景条目组
```

## 4. 创世回廊3.0 的大世界观融合模式

如果你的卡涉及多个世界观融合，参考创世回廊3.0：

```yaml
融合世界的设计要点:
  1. 统一舞台: 设计一个能容纳所有世界观的上层框架
     - 创世回廊使用"巨塔倒悬世界"作为统一舞台
  
  2. 分层管理: 每个子世界观作为独立层级
     - DNF（阿拉德）→ 楼层X层-X层
     - NGNL（游戏人生）→ 楼层X层-X层
     - SAO（刀剑神域）→ 楼层X层-X层
  
  3. 通用系统: 跨世界观通用的机制
     - 骰子/战斗/装备/强化/附魔/生产/经济/品级/属性检定
  
  4. 独立系统: 各世界观特有的系统保留在原世界楼层
     - 每个世界的特色只在该世界楼层内生效
  
  5. 穿梭机制: 玩家如何在各世界间移动
```

## 5. 世界观条目数量控制

| 卡的类型 | 建议世界书条目数 | 说明 |
|---------|---------------|------|
| 轻量日常卡 | 10-30条 | 只需角色设定+基本场景 |
| 中等RPG卡 | 30-80条 | 含规则系统+NPC+地点 |
| 大型世界卡 | 80-200条 | 多时代/多区域/复杂系统 |
| 超大型融合卡 | 200+条 | 多世界观融合（如创世回廊3.0约200条） |

**原则：宁精勿滥。** 与其写100条粗糙的条目，不如写50条精心设计的条目。

## 6. 世界书的组织文件结构

```yaml
世界书/
├── 核心规则/                    # 层级1
│   ├── {世界名}核心规则.txt
│   ├── NPC互动规则.txt
│   ├── 剧情演化规则.txt
│   └── 时间流逝机制.txt
├── 世界格局/                    # 层级2
│   ├── {时代}：世界格局.txt
│   └── {时代}：势力关系.txt
├── 年表与章节/                  # 层级3
│   ├── {时代}：剧情年表总纲（前期）.txt
│   ├── {时代}：剧情年表总纲（中期）.txt
│   ├── {时代}：剧情年表总纲（后期）.txt
│   └── {时代}：{章节名}.txt
├── 角色/                        # NPC设定
│   ├── {时代}：{角色名}.txt
│   └── ...
├── 地点/                        # 场景设定
│   ├── {时代}：{地点名}.txt
│   └── ...
├── 系统/                        # 子系统设定
│   ├── {时代}：{子系统}设定.txt
│   └── ...
├── 变量/                        # MVU变量相关
│   ├── [initvar]变量初始化勿开.yaml
│   ├── 变量列表.txt
│   ├── [mvu_update]变量更新规则.yaml
│   └── [mvu_update]变量输出格式.yaml
└── EJS控制器.txt                # 如使用EJS动态加载
```

## 7. 检查清单

写完世界观后，确认以下各项：

- [ ] 核心规则是否具体可执行（不是抽象概念）？
- [ ] 力量体系是否有明确的等级/获取/消耗机制？
- [ ] 各个条目的关键词是否一致（同一角色/地点的条目能被同时激活）？
- [ ] 互斥场景是否正确覆盖且不冲突？
- [ ] 条目顺序编号是否留了扩展空间？
- [ ] 常驻条目是否精简到最少（减少token消耗）？
- [ ] 条件触发的条目是否有明确且合理的触发关键词？
- [ ] 时代/章节切换逻辑是否正确？
