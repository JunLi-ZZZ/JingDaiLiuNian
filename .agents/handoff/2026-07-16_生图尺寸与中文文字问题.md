## 一、问题 1：代理完全无视 `--size`，画质不由请求尺寸控制

同一天、`--quality high`、同脚本实测：

| 请求尺寸 | 实际返回(脚本上报 width×height) | 总像素 | 画质 |
|---|---|---|---|
| `2048x2048`（2K，计费 0.06） | **1024×1024** | ~1.05 MP | 清晰，不糊 |
| `2160x3840`（4K 竖屏，计费 0.45） | **941×1672** | ~1.57 MP | 清晰 |
| `1024x1024`（1K，计费 0.03） | 180s 超时失败（疑似接口临时慢） | — | — |

**观测结论**

1. 代理**只保「宽高比」，不保像素**。请求 2048² 砍成 1024²；请求 2160×3840 压成 941×1672（比例 9:16 保住了）。
2. 代理像有**固定像素预算档**：观测到 ~1.05 MP（≈1024² 方形）与 ~1.57 MP（≈1254² 方形 / 941×1672 竖屏）两种。941×1672 与更早出现过的「清晰版」1254² 总像素几乎相同，像同一预算按比例摊开。
3. 因此请求 2K/4K 只是**多付费**，换不到承诺的分辨率。之前「焊 `--size 1536x1536` 拔高分辨率地板」的做法无效，已废弃。

**想请你判断/处理**

- 有没有办法让脚本/请求**稳定命中高像素预算档**（1.57 MP 那档画质更好）？是否有某个特定 `size` 或额外参数能触发？
- `image-assets.mjs` 的 size 校验（`normalizeOptions`，约 L135）只用正则卡「数字x数字」格式，不校验合法档位。若代理端有真实支持的尺寸/档位白名单，建议补校验并在 SKILL/REFERENCE 里给出真实列表。
- `SKILL.md`/`REFERENCE.md` 里把 `--size` 说成能控分辨率，与实测不符（只保比例、不保像素），建议改成真实行为，免得后人再踩。

## 二、问题 2：中文气泡文字随机崩成乱码（与画质无关）

- 「委屈掉泪」贴纸（上表 1024² 那张）：气泡要渲染「呜呜」，实际出的是拉丁乱码「crbugg」。**画是清楚的，只有字崩。**
- 而更早撞到 1.57 MP 高预算档时，「嘿嘿」「你好呀」等中文能正确渲染。
- 由此推翻旧判断「文字糊只是鬼图（低分辨率）的症状」：**文字崩与画质糊是两个独立问题**。目前观测到的相关性是：低预算档(1.05 MP) → 中文易崩；高预算档(1.57 MP) → 中文正确。样本还小。

**想请你判断/处理（这块最需要你的方案）**

1. 模型端 CJK 渲染既然不稳，是否改成「**出无字贴纸 + 后期合成中文气泡**」的流水线？例如脚本用真字体把气泡叠到 PNG 上，中文可 100% 正确。若走这条，需要你给出合成方案（字体、气泡样式、脚本改法）。
   - 备注：这些贴纸最终显示在一个 HTML 的手机面板里，理论上也能在前端用 CSS 叠气泡；但用户希望气泡尽量烤进图片以便当作可移植素材。两种都可讨论。
2. 若仍走模型烤字，能否连同问题 1 一起解决——稳定命中高预算档，让画质 + 中文一起达标？

## 三、最小可复现命令

```bash
# 2K 请求 → 实测回 1024×1024，中文气泡崩
node .agents/skills/gpt-image-assets/scripts/image-assets.mjs generate \
  --prompt '<白狐 chibi 贴纸；气泡内含 "呜呜">' \
  --output 'assets/stickers/委屈掉泪_2k.png' --size 2048x2048 --quality high --force

# 4K 竖屏请求 → 实测回 941×1672（比例保住，像素被压）
node .agents/skills/gpt-image-assets/scripts/image-assets.mjs generate \
  --prompt '<素凝月夜竖屏壁纸；无文字>' \
  --output 'assets/wallpapers/素凝_月夜_4k.png' --size 2160x3840 --quality high --background opaque --force
```

脚本上报的 `width/height` 就是判断代理是否无视 `--size` 的直接证据。
