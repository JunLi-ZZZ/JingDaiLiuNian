## 本次变化

脚本现在支持两个隔离的 provider：

| Provider  | 地址                       | Key 变量                | 默认质量 | 默认尺寸    | 本地图生图字段 |
| --------- | -------------------------- | ----------------------- | -------- | ----------- | -------------- |
| `aipaiai` | `https://aipaiai.cn/v1`    | `AIPAIAI_IMAGE_API_KEY` | `2K`     | `1536x1024` | `image[]`      |
| `zyuou`   | `https://api.zyuou.com/v1` | `ZYUOU_IMAGE_API_KEY`   | `high`   | `1536x1536` | `image`        |

- 用 `.env.image.local` 中的 `IMAGE_PROVIDER=aipaiai|zyuou` 选择默认站，也可单次传 `--provider`。
- 如果两把专用 Key 同时存在但未指定 provider，脚本会拒绝请求，避免扣错余额。
- 进程级通用 `ZYUOU_API_KEY` 仍被忽略；旧本地文件中的同名变量仅保留迁移兼容。
- Aipaiai 客户端现接受所有满足 GPT Image 官方约束的自定义尺寸；`1536x1024` 与 `3840x2160`
  已真实验证，其余合法尺寸仍取决于中转站是否接受。
- Aipaiai 使用 `quality=1K|2K|4K`，不发送该教程未声明的 `output_format` 或 `background`。
- Zyuou 原请求格式、尺寸校验和尺寸异常警告继续保留。
- Codex 与 `.claude/skills/gpt-image-assets/SKILL.md` 都指向同一规范和脚本。

## 关键结论

Aipaiai 会遵循已测试的显式 `size`。之前的 157 万像素正是 `1536x1024` 的乘积，并非中转站压缩；明确请求 `3840x2160`
后成功得到完整 829 万像素。`quality=1K|2K|4K` 与像素尺寸是两个独立参数。默认继续使用价格相同的 `2K + 1536x1024`
适合普通素材，需要真实 4K 像素时必须同时传 `--quality 4K --size 3840x2160`（或尚未实测的竖版
`2160x3840`），并读取脚本报告的实际尺寸。

不要为猜测映射关系连续发起付费测试。后续只有在用户明确同意或站长给出新的尺寸语义后，再设计重复样本矩阵。
